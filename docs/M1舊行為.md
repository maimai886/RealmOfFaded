# M1 舊行為

M1 要照做的舊專案行為和數字。路徑都在 `../Sproutia` 底下，寫成 `檔:行`。只列 M1 用得到的，其他的等到用到再回舊專案查。

## 1. 封包

### 信封

- 格式 `{"v":1,"t":類型,"id":整數,"d":{}}`，剛好四個欄位，多一個就不收 — `src/net/protocol.gd:17,398-399,419-422`
- 單則上限 8192，字元數或 UTF-8 位元組數有一個超過就算 — `protocol.gd:22,407`
- 檢查順序：大小、JSON、`v`、信封欄位、`t` 認不認得、`id` — `protocol.gd:403-431`
- `id` 要是安全整數，最大 2^53−1，小數、字串、1e300 都算信封壞掉 — `protocol.gd:24,421,704-709`
- 請求和 `resp` 的 `id` 至少 1，推送一律 0；同一條連線的請求 `id` 要比上一個通過的大，可以跳號 — `protocol.gd:444-447`、`server/security/rate_limiter.gd:87-91`
- 欄位只留 schema 裡有的，多的丟掉；沒寫 `required: false` 就是必填 — `protocol.gd:472-484`
- 整數欄位接受 `12.0`，先用浮點比範圍再轉整數；浮點欄位拒 NaN 和無限大 — `protocol.gd:519-546`
- 字串欄位一律拒 0x00–0x1F、0x7F、C1 控制字元、雙向控制、行段分隔、代理區、非字元；`id` 格式只能小寫英文、數字、底線，1–32 字 — `protocol.gd:54,92,549-565,591-606`
- 回應一定帶 `reason`，成功是空字串 — `server/net/session.gd:272-275`
- 解析前擋掉超過 64 字元或指數超過 400 的數字、`\u0000` 跳脫，都當 `bad_json` — `protocol.gd:27-28,409,644-697`

### 伺服器收到一則訊息的處理順序

`server/net/session.gd:185-228`

1. 解碼失敗：`too_large`、`bad_json`、`bad_envelope`、`bad_version` 直接踢；`unknown_type`、`bad_id` 記一次違規，不回應 — `session.gd:42-43,189-195`
2. 頻率桶不夠：回 `rate_limited`，記違規 — `session.gd:198-202`
3. `id` 沒有遞增：回 `bad_id`，記違規 — `session.gd:203-206`
4. 欄位驗證失敗：回 `{ok:false, reason, field}`，記違規 — `session.gd:207-211`
5. 登入狀態 — `session.gd:38-40,231-264`
   - 不用登入：`auth.login`、`server.list`、`ping`
   - 沒登入送別的：回 `not_logged_in`，記違規
   - 大廳指令 `char.*` 在地圖裡送：回 `in_world`
   - 沒進地圖送遊戲指令：回 `not_in_world`
6. 處理中產生的推送排在這則 `resp` 後面 — `session.gd:76,213-227`

- 5 秒內違規 20 次踢 `violations`；待送超過 4096 則踢 `slow_client` — `rate_limiter.gd:31-32`、`session.gd:20,121-122,311-313`
- 被遊戲規則拒絕不算違規；10 秒內被拒 100 次只寫一筆稽核 — `session.gd:34-35,290-308`

### 連線、逾時、踢人

- 沒登入 30 秒踢 `login_timeout`；登入後 20 秒沒收到任何訊息推一次 `heartbeat`，客戶端回 `ping`；60 秒沒訊息踢 `idle_timeout`；每秒檢查一次 — `game_server.gd:82-89,353-366`、`game_client.gd:657-659`
- 同一個 IP 最多 10 個 Session，多的踢 `too_many_connections` — `game_server.gd:86,319-321`
- 傳輸層：全服 200 條、同 IP 10 條、同 IP 10 秒新開 30 條、握手 5 秒；二進位訊框踢 `binary_frame`、壞 UTF-8 踢 `bad_utf8` — `server/net/ws_server.gd:13-38`
- 送完 `kick` 約 200 毫秒後用關閉代碼 4000 關 — `ws_server.gd:34-36`
- 同帳號第二條連線登入成功時踢舊的 `duplicate_login` — `auth_service.gd:275-277`
- 沒有登出訊息，斷線就是登出：存檔、離開地圖、看得到他的人收到 despawn — `game_server.gd:346-349,455-497`、`map_instance.gd:408-416`
- 客戶端等待上限：請求 8 秒、連線 3 秒、`char.enter` 之後等 `world.enter` 15 秒 — `game_client.gd:35-41,336-355`

### 登入

- 帳號不存在就自動註冊，帳號一律轉小寫比對 — `auth_service.gd:5,150,182-189`
- `client_version` 和伺服器的 `CLIENT_VERSION` 字串完全相同才放行 — `auth_service.gd:153-154`、`protocol.gd:20`
- 同一個來源每分鐘 30 次登入嘗試、每小時 20 次註冊，超過回 `rate_limited` — `auth_service.gd:31-35,155-157,185-187`
- 來源是 IPv4 位址或 IPv6 的 /64 前綴 `server/security/ip_source.gd:8`；帳號加來源 5 分鐘內錯 5 次，這一組鎖 5 分鐘 `locked`；同一個來源錯 7 次整個來源封 5 分鐘 `ip_banned`；帳號本身永遠不鎖；3 個以上來源猜同一個帳號寫一筆稽核 — `server/security/login_guard.gd:16-29`
- 密碼 PBKDF2-HMAC-SHA256 600000 輪、鹽 16 位元組、金鑰 32 位元組 — `server/security/password_hash.gd:15-22`
- 雜湊丟背景算，不能卡住地圖 tick；全服同時算 CPU 核心數減 1、至少 2 個；每個來源 2 個；滿了回 `server_busy` — `auth_service.gd:39-51,162-164,194-196`
- 限速、鎖定、並發上限都在丟進背景之前檢查 — `auth_service.gd:143-164`
- 同一條連線上一次登入還在算又送一次回 `login_pending`；算到一半斷線結果丟掉、註冊不建立，猜錯照樣累計鎖定 — `auth_service.gd:146-147,219-238`
- 客戶端收到 `server_busy` 等 1 到 2 秒的隨機時間自動重送一次 — `game_client.gd:28,50-52`

- bounds 的 max 要大於 min — `map_data.gd:244-249`
- blocker 格式：`{"type":"rect","min":[x,z],"max":[x,z]}` 要有面積，或 `{"type":"circle","center":[x,z],"radius":r}` 半徑大於 0 — `map_data.gd:629-645`

- 擺設形狀照 `data/props.json` 的 footprints — `src/core/prop_footprints.gd:92-107,169-193`
  - `blocks` false 不擋；沒登記的也不擋
  - `circle`：半徑乘 scale
  - `square`：半邊長 = radius × scale × 0.8862，軸對齊，不跟 rotation_y 轉
  - `rect`：half 乘 scale，轉 rotation_y 之後取外接軸對齊矩形
  - `parts` 每塊的 offset 乘 scale 再照 rotation_y 轉
  - 半徑或半邊小於 0.01 丟掉
- 草原的三種擺設都是 square：tree_broadleaf 0.76、shrub 0.8、boulder 0.75 — `data/props.json:1128-1145`
- 擺設形狀壓到必要點就整塊丟掉：出生點和存檔點周圍 0.8 公尺、傳送點周圍 0.8 和半徑取大、NPC 和怪物群中心 0.25 — `map_data.gd:67-71,289-291,725-756`、`prop_footprints.gd:129-152`
- 出生點不可走的地圖整張不合法；客戶端不自己算 props，用 `world.blockers` 送來的總表 — `map_data.gd:303-305`、`src/world/net_session.gd:1837-1857`

## 4. 移動

- 移動速度 3.5 公尺每秒：jobs.json 的初心者沒有 move_speed，角色資料也沒有，用預設值 — `battle_world.gd:136,525-526,1845-1849`
- 伺服器在 `self.stats.move_speed` 送實際速度，客戶端預測用它 — `map_instance.gd:599`、`net_session.gd:2020-2021`
- tick 50 毫秒，每張地圖照伺服器時鐘補跑到期的 tick，落後超過 20 個就丟掉多的時間 — `battle_world.gd:132-134`、`map_instance.gd:35-37,335-345`
- 主迴圈每輪先收訊息、跑登入收尾、推進地圖、每秒檢查 Session — `game_server.gd:787-806`

點地，客戶端

1. 滑鼠射線打到地面，吸到 0.6 公尺格子的中心；那一格中心不可走就不送 — `src/input/player_input.gd:254-266,456-459`、`src/core/move_grid.gd:17-34`
2. 目標再 `push_out` 一次 — `net_session.gd:1571-1579`
3. 按住左鍵拖著走，換到別的格子才送新目標 — `player_input.gd:313-324`
4. 節流：兩則移動指令至少隔 50 毫秒；目標和上一則差不到 0.25 公尺不送；從走切到停立刻送；座標取到 0.001 — `src/net/move_throttle.gd:9-16,60-92`
5. 伺服器回失敗時下一則移動一定重送 — `net_session.gd:1469-1472`

0.6 公尺的點擊格子和 0.5 公尺的尋路格子是兩回事，伺服器不知道點擊格子 — `move_grid.gd:1-6`

伺服器驗證 `move.to`

- 死了回 `dead` — `player_commands.gd:225-226`
