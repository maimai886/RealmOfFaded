# 上線架構檢查

2026-09-16 使用者要求確認架構能不能撐起：Mac、Windows、手機三種客戶端，伺服器放雲端。
這份是實際翻過程式之後的結論，不是規劃願望。

## 已經是對的，不用改

- **邏輯和表現分離**：`src/core/` 是純邏輯不依賴場景節點，伺服器和客戶端共用同一份規則，
  所以伺服器本來就能 headless 跑在沒有畫面的機器上
- **資料庫有抽象層**：`server/db/database.gd` 是介面，現在有 json 檔和記憶體兩種實作，
  註解也寫明之後換 SQLite 或 PostgreSQL 照這份介面實作即可。雲端要換儲存不用動業務邏輯
- **伺服器權威**：客戶端只送意圖，所有結果由伺服器決定，這是連線遊戲上雲的前提
- **手機那一側**：Mobile 算繪器、ASTC 貼圖變體、手機版面、觸控搖桿都已經在了

## 真正擋路的四件事

第 1、3 條 2026-09-27 做完，第 2、4 條還沒做。

### 1. 伺服器綁定位址，已做完

`server/main.gd` 加了 `--bind=` 參數，預設維持 `127.0.0.1` 只有本機連得到；可以給 IPv4、IPv6 位址或 `*` 代表所有網路介面，
主機名稱不收。綁 `127.0.0.0/8`、`::1` 以外的位址時啟動會印警告。伺服器本身只講 ws 不做 TLS，
對外一定要在前面擺做 TLS 終結的反向代理，玩家連 wss，防火牆只開代理的 port。
雲端最簡單的擺法是伺服器照樣綁 `127.0.0.1`，同一台機器的代理連進來，根本不用改綁定。
規則寫在 `docs/伺服器架構.md` 第 2 節，測試在 `tests/test_server_bind.gd`。

### 2. 客戶端連線位址是寫死的

`src/net/game_client.gd` 的 `DEFAULT_URL` 是本機位址，伺服器列表也是本機產生的。
要連雲端就要有真的伺服器清單來源和可設定的位址。現在有 `--server=` 參數可以覆蓋，
那是開發用的，不是正式作法。

### 3. 密碼雜湊，已做完

原本是 salt 加密碼跑一次 SHA-256，拿到資料庫的人可以極快地暴力破解。
現在是 PBKDF2-HMAC-SHA256，Godot 沒有 bcrypt、scrypt、Argon2，只能用內建 HMAC 照 RFC 8018 自己組，
用 RFC 7914 的向量驗過。輪數照 OWASP 2023 的 600000 次。存的格式帶演算法、輪數、鹽，之後加輪數或換算法不用動舊資料；
舊格式的帳號登入成功當下改存新格式，密碼錯不動。

GDScript 算一次約 0.8 秒，所以放到 WorkerThreadPool，登入改成非同步回應，主迴圈不再停：
登入進行中另一條連線的 ping 從 759 毫秒回到 15 毫秒以內。背景同時最多算 4 個、每個 IP 1 個，超過回忙碌。
細節和實測數字在 `docs/伺服器架構.md` 第 5 節和第 11 節，測試在 `tests/test_security_password.gd`。
留下的是吞吐量，一秒大約 5 次登入，真的開服前看人數再決定要不要加背景名額或分出登入伺服器。

### 4. Windows 沒有匯出設定

`export_presets.cfg` 只有 macOS、Android、iOS 三個，Windows 要補。
另外 **Godot 的匯出範本還沒安裝**，大約 1 GB，要先問使用者才能下載。

## 還沒查、上線前要查的

- HMAC 簽章金鑰現在放哪裡、怎麼輪替，雲端不能跟著程式一起進版本庫
- 單一行程能撐多少人，要不要分地圖行程；現在是一個行程跑全部地圖
- 存檔備份和還原流程
- 伺服器更新時怎麼讓玩家不掉線，或至少是可預期的維護
- 日誌和監控要送到哪裡

## 順序建議

1 和 3 做完了。接著做 2，沒有它連不到雲端；4 看什麼時候要真的出手機和 Windows 版。
