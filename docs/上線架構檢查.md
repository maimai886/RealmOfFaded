# 上線架構檢查

2026-09-16 使用者要求確認架構撐得起 Mac、Windows、手機三種客戶端，伺服器放雲端。以下照 Rust 新專案的現況寫。

## 已經對的

- 伺服器是獨立的 Rust 執行檔，不用 Godot，Linux 直接部署；純邏輯在 `rof-core`，伺服器和客戶端共用
- 伺服器權威，客戶端只送意圖
- 密碼 PBKDF2-HMAC-SHA256 六十萬輪，在背景算不卡地圖 tick
- 手機：專案設定已經打開 `import_etc2_astc`，手機拿得到 ASTC；Android 和 iOS 的編譯風險寫在 `Rust重構規劃.md` 第 8 節

## 上線前要做的

1. **對外連線**：伺服器只綁 `127.0.0.1`，本身只講 ws 不做 TLS。雲端做法是同一台機器擺做 TLS 終結的反向代理，玩家連 wss，防火牆只開代理的埠；代理在別台機器時才要加綁定參數
2. **客戶端連線位址**：現在靠 `--server=主機:埠`，預設 `127.0.0.1:7780`，那是開發用的。正式要有真的伺服器清單來源和可設定的位址
3. **存檔**：M1 的資料庫在記憶體，M3 要照 `Rust重構規劃.md` 第 3 節做簽章存檔；之後換資料庫只換儲存那一層
4. **匯出設定**：新專案還沒有 `export_presets.cfg`，Godot 匯出範本也沒裝，約 1 GB，下載前先問使用者。排除清單要有 `server_data/*`、`*.key`、`tests/*`、`art_source/*`、`art_pipeline/*`；`rust/` 有 `.gdignore`，伺服器程式和設定本來就不會進包

## 還沒查的

- 簽章金鑰 `ROF_SERVER_SECRET` 在雲端怎麼存、怎麼輪替
- 單一行程撐多少人，要不要照地圖分行程
- 存檔備份和還原流程、伺服器更新時怎麼維護、日誌和監控送到哪裡
