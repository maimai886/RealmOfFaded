1. `CLAUDE.md`、`遊戲總規格.md`、`Rust重構規劃.md`，寫法照 `程式規範.md`

## 2. 建置與驗證

Rust 指令在 `rust/` 底下跑，其他在根目錄，完整參數和 Godot、Blender 的位置在 `開發指令.md`。

- Rust 測試 `cargo test --workspace` 要全過；動到擴充或介面再 `cargo build -p rof-gdext`，跑客戶端冒煙 `godot --headless --path . --script res://tests/smoke.gd`
- 美術管線測試：`blender -b --factory-startup --python-exit-code 1 -P art_pipeline/tests/run.py`
- 看畫面：客戶端或 `scenes/dev/` 的預覽場景加 `--shot=路徑` 截圖，截完自己看過再交

## 5. 容易踩的坑

- 7777 到 7780 是使用者的，崗位自己的連線測試用 7812 以後的埠，只關自己記下 PID 的那一個，不准用程式名稱整批關
- Windows 上 Godot 開著會鎖擴充的 DLL，編擴充會失敗；只能關自己開的 Godot，使用者的遊戲不准關。常調的數字放 `data/*.json` 就不用重編
- 舊 JSON 的整數常寫成 `1.0`，讀的時候用 `rof_data::lenient_i64`；隨機數換成 PCG32，舊測試指定種子的數字不能照抄
- 測試要改資料就複製一份，不准暫時改別人的檔再蓋回去
- 介面從舊專案搬過來改接擴充，不要重打，配色和版面是使用者一輪輪退件調出來的
- 舊文件裡 `src/world/`、`server/`、`tests/*.gd` 這類路徑指的是 `../Sproutia`；`mock/` 是未追蹤的資料夾，不要引用也不要提交
