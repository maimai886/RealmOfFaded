## 0. 總開關：現在是關的

2026-09-16 使用者：「我這個遊戲暫時不需要任務 我要原版ＲＯ那樣啥都不教你 不限制你」。

程式和資料都留著，`data/quests.json` 最外層的 `enabled` 是 false，沒寫當作開著。關著時整套當作不存在：
- 接、交、放棄一律回 `unknown_quest`，不推送 `quest.state`
- NPC 對話的任務選項條件全部過不了，委託入口另外掛 `feature:quests` 條件

改成 true 就整套回來，不動程式。測試要同時守住開和關兩邊。以下是開著時的規格。

## 1. 資料

欄位說明寫在 `data/quests.json` 的 `notes`，重點：
- 發放者 `giver`、交付者 `turn_in` 都是 `data/npcs.json` 的 NPC id
- `tutorial` 不能放棄；`auto` 條件符合時進遊戲自動接；`repeatable` 可以再接
- 前置 `prerequisites`：基本等級、職業等級、職業、先完成的任務
- 目標最多 8 個，九種：talk、kill、collect、buy、use_item、learn_skill、save_point、reach_map、job_level
- 計數型的進度由伺服器從真實事件累加後存檔；collect、learn_skill、job_level 每次從角色現況算，改存檔偽造不了
- kill 只算擊殺者，隊友分經驗不算
- 獎勵 `rewards`：經驗、職業經驗、金幣、道具；對白 `dialogue` 分接下、進行中、完成

現有內容：八個新手教學任務和八個野外任務，教學做完大約基本等級 5。

## 2. NPC 對話

- 選項用條件 `quest_state:<任務id>:<狀態>` 過濾，狀態是 `available`、`active`、`ready`、`done`，同一時間只出現一個
- 動作 `quest:<任務id>` 接任務、`quest_done:<任務id>` 交任務，伺服器再查一次發放者、前置、目標
- 對話文字寫 `@任務id.accept` 時取自 `quests.json` 的 `dialogue`，不在 `npcs.json` 抄第二份

## 3. 防作弊

- 接和交都在伺服器重查前置、狀態、目標；收集類交的時候背包要真的有
- 交任務要同地圖、活著、3 公尺內，而且 NPC 要是那個任務的交付者
- 獎勵在同一個指令裡做完並存檔；一次性任務交完不能再接
- 客戶端唯一能指定任務 id 的是放棄；亂送 id 回 `unknown_quest`
- 同時進行上限 30 個，進度夾在 0 到需求數，讀檔再夾一次
- 金幣照舊走共用的改錢函式並稽核

## 4. 介面

- 任務視窗 `Alt+U`：左邊清單分進行中和已完成，右邊委託人、說明、目標進度、獎勵、放棄鈕
- 任務追蹤掛在狀態板下面，最多 3 個任務、每個 3 個未完成目標；設定可以關
- 進度來自伺服器推送；名稱和目標文字客戶端自己讀 `quests.json`
