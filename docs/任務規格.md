# Realm of Faded 任務系統與新手教學

2026-09-16 訂。資料在 `data/quests.json`，純邏輯在 `src/core/quest.gd`，伺服器在 `server/services/quest_service.gd`，
介面在 `src/ui/quest_window.gd` 和 `src/ui/quest_tracker.gd`。
和其他系統一樣：資料驅動、伺服器權威、客戶端只顯示。

## 0. 總開關：現在是關掉的

2026-09-16 使用者的要求：「我這個遊戲暫時不需要任務 我要原版ＲＯ那樣啥都不教你 不限制你」。
所以任務系統整套關掉，但程式和資料一行都沒刪，只是加了一個開關。

開關在 `data/quests.json` 最外層：

```json
{ "enabled": false, "quests": { ... } }
```

沒寫 `enabled` 時當作開著。`src/core/quest.gd` 的 `Quest.enabled()` 讀它，
`Quest.load_default()` 在關著時回傳空字典，`Quest.load_all()` 不看開關、永遠回傳整份資料。

關掉時會發生的事，一條也不例外：

| 位置 | 關掉的行為 |
|---|---|
| `game_server.gd` | `quests_enabled` 為 false，`quest_data` 是空的；測試可以用 options 的 `quests_enabled` 覆寫 |
| `quest_service.gd` | `accept`、`turn_in`、`abandon` 一律回 `unknown_quest`，`view` 回空的，`states` 和 `dialogue_texts` 是空字典 |
| `map_instance.gd` | 進地圖和每個 tick 都不推送 `quest.state`，客戶端收不到任何一則 |
| NPC 對話 | 任務選項的條件 `quest_state:...` 因為狀態是空的而全部過不了；委託入口另外掛 `feature:quests` 條件，整段消失 |
| `hud.gd` | 不建任務視窗、不建任務追蹤，Alt+U 沒有作用，`--dev-open=quest` 也不會有訊息 |
| `settings_window.gd` | 按鍵分頁不列「任務視窗」那一行 |

要整套開回來只要把 `data/quests.json` 的 `enabled` 改成 `true`，不用動程式。
`tests/test_quest_switch.gd` 同時守住關掉和打開兩邊的行為，
`tests/test_quest_server.gd` 和 `tests/test_security_quest.gd` 一律用 `quests_enabled: true` 開著測任務本身。

底下第 1 到第 8 節寫的是任務系統開著時的規格，開關關著時這些都不會發生。

## 1. 參考來源

| 來源 | 看的是什麼 | 這裡怎麼做 |
|---|---|---|
| rAthena `db/re/quest_db.yml` | 任務定義的欄位：`Id`、`Title`、`TimeLimit`、`Targets`（`Mob` 加 `Count`）、`Drops` | 同樣是一個任務一筆、目標是清單；欄位擴充成九種目標，見第 2 節 |
| rAthena `src/map/quest.cpp` 的 `quest_add`、`quest_delete`、`quest_update_objective`、`quest_update_status` | 接任務、放棄、進度累加、完成狀態三段式 | `quest.gd` 的 `accept`、`abandon`、`apply_event`、`finish` 對應這四個動作 |
| rAthena 角色資料庫的 `quest` 表：`char_id`、`quest_id`、`state`、`count1..3` | 進度跟著角色存檔，不是跟著地圖 | 進度存在角色紀錄的 `character.quests`，跟著 HMAC 簽章，見第 5 節 |
| rAthena `src/map/mob.cpp` `mob_dead` 呼叫 `quest_update_objective` | 打怪的進度在怪物死亡時累加 | `map_instance.gd` 收到 `death` 事件時只算給 `killer` 那個玩家 |
| rAthena 的任務目標只有獵殺和掉落兩種，上限是 `MAX_QUEST_OBJECTIVES` | 目標種類很少，所以腳本要自己寫很多判斷 | 目標種類擴充成九種，教學不用另外寫腳本；一個任務最多 8 個目標 |
| RO 的任務視窗（Alt+U，封包 `ZC_ALL_QUEST_LIST`） | 左邊清單、右邊內容、分「進行中」和「已完成」 | `quest_window.gd` 照這個版面，另加放棄鈕 |
| 舊版新手村 Novice Training Grounds，`npc/pre-re/jobs/novice/novice.txt` | 教官依序教移動、攻擊、用道具、存檔點，練到 Job Lv 10 才轉職 | 教學線照這個順序，見第 6 節 |
| 新版新手村 Criatura Academy，`npc/re/jobs/novice/academy.txt` | 每個教官各發一個小任務，做完給經驗、藥水和少量金幣 | 三位導師各發一個任務，獎勵同樣是經驗加藥水加金幣 |
| rAthena `npc/kafras/functions_kafras.txt` 的 `getskilllv("NV_BASIC")` | 基本技能等級決定能用什麼功能 | 教學裡的「基本功」任務要求基本技能 1 級，倉庫 6 級的規則不變 |

## 2. 任務資料 data/quests.json

```
"quests": { "任務id": { 欄位 } }
```

| 欄位 | 內容 |
|---|---|
| name | 顯示名稱 |
| giver | 發任務的 NPC id，要在 `data/npcs.json` 裡 |
| turn_in | 交任務的 NPC id，沒寫就是 giver |
| summary | 任務視窗裡的說明 |
| tutorial | true 代表教學任務，不能放棄 |
| auto | true 代表條件符合時進遊戲自動接下，目前只有第一個教學任務是 |
| repeatable | true 代表完成後可以再接 |
| prerequisites | `base_level`、`job_level`、`jobs`（職業 id 清單）、`quests_done`（要先完成的任務 id） |
| objectives | 目標清單，最多 8 個，格式見下表 |
| rewards | `base_exp`、`job_exp`、`gold`、`items`（`{item_id, amount}`） |
| dialogue | `accept` 接下時的說明、`progress` 還沒完成時的回應、`complete` 交任務時的回應 |

### 目標種類

| type | 欄位 | 進度怎麼來 |
|---|---|---|
| talk | npc | 和這個 NPC 說到話，`npc.talk` 通過距離檢查的當下 |
| kill | monster, count | 自己打倒這種怪物，只算擊殺者 |
| collect | item, count | 背包裡現在有幾個，交任務時收走 |
| buy | item, count | 向 NPC 商店買到的數量 |
| use_item | item, count | 真的用掉的次數 |
| learn_skill | skill, level | 角色現在的技能等級 |
| save_point | — | 在 NPC 這裡登記過存檔點 |
| reach_map | map | 走到過這張地圖 |
| job_level | level | 角色現在的職業等級 |

- **計數型**：talk、kill、buy、use_item、save_point、reach_map。進度由伺服器從事件累加後存檔，達到需求就不再加。
- **即時型**：collect、learn_skill、job_level。存檔裡沒有數字，每次都從角色和背包現況算，所以改存檔也偽造不出來。

## 3. 數值調整

新手做完教學線的目標是 Base Lv 5 左右、身上留得下兩瓶以上的紅色藥水錢。

| 項目 | 數字 | 理由 |
|---|---|---|
| 教學線基本經驗合計 | 5700 | 1 到 5 級需要 548 + 894 + 1486 + 2173 = 5101，照 `data/exp_tables.json` 的 renewal 表 |
| 教學線職業經驗合計 | 260 | 初心者 1 到 10 級要 1151，剩下的要自己打怪，「綻放之時」就是要玩家去草原練到 Job Lv 10 |
| 教學線金幣合計 | 700 | 紅色藥水一瓶 50，扣掉教學裡自己買的那瓶還有 650，夠買 13 瓶 |
| 起始金幣 | 0 | 不變，照 rAthena `start_gold`；第一個任務就給 100 金幣，玩家才買得起教學要用的藥水 |

`tests/test_quest.gd` 的 `test_tutorial_rewards_reach_base_level_five` 會把這三個數字算一次，改任務獎勵而沒到 Base Lv 5 會失敗。

## 4. NPC 對話整合

- 對話樹的選項用條件 `quest_state:<任務id>:<狀態>` 過濾，狀態是 `available` 可以接、`active` 進行中、`ready` 可以交、`done` 已完成
- 對話動作 `quest:<任務id>` 接任務、`quest_done:<任務id>` 交任務；兩個都由 `quest_service` 再檢查一次發放者、前置、目標
- 節點的 `text` 寫成 `@任務id.accept` 時，內容取自 `data/quests.json` 的 `dialogue`，任務說明不用在 `npcs.json` 抄第二份
- 每個任務在同一個 NPC 的 hello 節點放三個選項，狀態互斥，同一時間只會出現一個
- `player_commands._context` 把 `quest_states` 和 `quest_text` 放進對話 context，`dialogue.gd` 只負責查表，不含任務規則

## 5. 防作弊

| 攻擊 | 擋法 |
|---|---|
| 沒達到前置就接任務 | 對話選項本來就不會列出來；`quest_service.accept` 再查一次前置、是否已接、是否做過 |
| 目標沒完成就交任務 | 回報選項不會出現；`turn_in` 再算一次目標，收集類的還要背包真的有東西 |
| 改存檔的進度 | 角色紀錄有 HMAC 簽章，改了就整份隔離；就算簽章被繞過，收集、學技能、職業等級都是現算的 |
| 重複交任務、一次性任務再接 | 交完就從 `active` 移到 `done`，`repeatable` 為 false 的不能再接 |
| 離開 NPC 之後才交 | `npc.choose` 本來就檢查同地圖、活著、3 公尺內；交任務還要 NPC 和任務的 `turn_in` 一致 |
| 交任務當下拔線想拿兩次 | 獎勵在同一個指令裡做完，`save_requested` 讓這個 tick 結束就存檔；斷線走 `leave_world` 一樣會存 |
| 亂送任務 id | 協定擋格式，服務層回 `unknown_quest`；`quest.abandon` 是客戶端唯一能指定任務 id 的訊息 |
| 別人打的怪算自己的 | 只有 `death` 事件裡的 `killer` 拿到進度，隊伍分經驗的人不算 |
| 灌大存檔 | 同時進行的任務上限 `MAX_ACTIVE` 30，進度數字夾在 0 到需求數量，讀存檔時 `sanitize_state` 再夾一次 |

稽核事件：`quest.accept`、`quest.turn_in`（帶經驗、金幣、升了幾級）、`quest.abandon`、`quest.item_taken`、`quest.item_reward`；
獎勵的金幣照舊走 `game_server.change_gold`，所以另有一筆 `gold.change`。

惡意客戶端測試在 `tests/test_security_quest.gd`，正常流程在 `tests/test_quest_server.gd`，純邏輯在 `tests/test_quest.gd`。

## 7. 介面

- **任務視窗**：`Alt+U`，動作名稱 `win_quest`，可以在設定的按鍵分頁改鍵。左邊清單分「進行中」「已完成」，右邊是委託人、說明、目標進度、獎勵和放棄鈕；教學任務的放棄鈕停用並寫明原因
- **任務追蹤**：HUD 右側小地圖下面，最多列 3 個任務、每個最多 3 個還沒完成的目標，完成的顯示「回去回報」；按標題會打開任務視窗並跳到那個任務
- 設定的介面分頁 `show_quest_tracker` 可以關掉追蹤，預設開啟
- 進度一律來自伺服器推送的 `quest.state`；任務名稱、目標文字、獎勵由客戶端自己讀 `data/quests.json`，和 NPC 外觀讀 `npcs.json` 的做法一致
- 目標的文字由 `ui_text.gd` 的 `quest_objective_text` 產生，視窗和追蹤器共用一套說法
