# 多國語系規劃

2026-09-16 使用者定案：之後要支援多國語系，現在先把工作流準備好，讓以後改文案和翻譯都輕鬆。
這份是做法和規矩，還沒有整批轉換，但**從現在起寫的新程式一律照這裡的規矩**，不要再加新的債。

## 現況

2026-09-25 起文字表先用 `locale/zh_TW.json`，程式用 `src/core/texts.gd` 的 `Texts.text(鍵, {參數})` 取字。
用 JSON 不用 CSV，是因為 Godot 會把 CSV 匯入成翻譯資源，匯出和無頭測試都要多一步；之後整批轉換成 `tr()` 時再一起換。

`src/` 和 `server/` 裡大約有 1300 條直接寫死的中文字串，另外 `data/*.json` 裡還有道具名、技能名、
怪物名、NPC 對話。兩種要分開處理，因為一個是程式碼、一個是內容。

## 做法

### 程式裡的字

用 Godot 內建的翻譯：字串換成鍵，透過 `tr()` 取值，翻譯放在 `locale/<語言>.csv`，
在 `project.godot` 註冊。繁體中文是原文語言，也一樣要有一份表，這樣改文案只要改表不用動程式。

鍵的命名用「畫面或模組.用途」，例如 `ui.inventory.title`、`shop.not_enough_gold`、`dialogue.close`。
不要用整句中文當鍵，句子一改鍵就跟著變，翻譯就全部失效。

帶數字或名字的句子用具名參數再 `format`，不要用字串相接。
不同語言的語序不一樣，相接出來的句子沒辦法翻。

### 資料裡的內容

`data/*.json` 的 `name`、`description`、NPC 對話這些，做法是原檔只留鍵或只留原文，
另外一份 `data/locale/<語言>/*.json` 放對應的翻譯，讀資料的時候套上去。
選哪一種等真的要做的時候決定，但**兩種都不可以把翻譯塞回原本的資料檔**，
不然資料檔會變成多語言混在一起，之後加語言就要整份重寫。

### 伺服器

伺服器不翻譯。錯誤原因一律回**代碼**不是句子，例如 `not_enough_gold`，
由客戶端決定要顯示成哪一國語言的哪一句。現在已經有一部分是這樣做的，
剩下直接回中文句子的地方要一起改掉。這件事本身就是對的，
就算不做多國語系，伺服器回句子也是把顯示層的責任放錯地方。

## 規矩

- 新寫的玩家看得到的字，一律走文字表，不要直接寫在程式裡
- 伺服器回代碼不回句子
- 需要組句子的地方用具名參數，不要用相接
- 註解、log、稽核紀錄不必翻譯，那是給開發看的

## 什麼時候整批轉換

等同時在跑的工作收斂、測試回到全綠再做。整批轉換會動到幾乎每一個介面檔案，
現在十條線同時在改，這時候做一定會互相蓋掉。
