# Realm of Faded 怪物行為

2026-09-16 訂。每一種行為都寫在 `data/monsters.json` 的 `behavior` 欄位，決策在 `src/core/monster_ai.gd`，
執行在 `src/core/battle_world.gd`，測試在 `tests/test_monster_behavior.gd`。

行為全部由伺服器決定，客戶端只收事件並播特效。決策每 200 毫秒跑一次，和 `AI_TICK_MS` 對齊，
所有判斷只看當下的實體快照，沒有隱藏狀態，所以同一個亂數種子每次跑出來的結果都一樣，
一次推進 6 秒和分 20 次推進的事件流完全相同，由 `test_behaviours_are_deterministic_and_step_size_independent` 守住。

---

## 1. 資料長什麼樣

```json
"ash_wolf": {
  "behavior": {
    "pack": {"group": "ash_wolf", "radius": 8.0, "cooldown_ms": 8000, "max_join": 3}
  }
}
```

`behavior` 底下每一個鍵是一種行為，沒寫就是沒有。一隻怪可以同時有好幾種，
例如骨弓手同時有 `kite` 和 `pack`，灰蝕巫長同時有 `kite`、`cast`、`summon`。

沒有 `behavior` 的怪維持原本的規則：被動怪被打才還手，主動怪在 `detect_range` 內索敵，
離出生點超過 `chase_limit` 就放棄回家，`assist` 為 true 的怪在 6 公尺內看到同種同伴開打就跟著上，資料寫 `assist_range` 可以改這個距離。成群的小怪要縮小，因為加入的同伴又會拉它旁邊的同伴，小樹苗一群五六隻、半徑五公尺多，用 6 公尺的話打一隻就是整群上來，所以小樹苗是 3 公尺。主動怪的 `detect_range` 沒寫是 6 公尺，成群的主動怪也要縮：水晶兔一群四隻、半徑五公尺，6 公尺的話走近一群就是四隻一起撞過來，所以水晶兔是 4 公尺。

`tests/test_world_content.gd` 的 `test_every_monster_behaviour_field_is_understood` 會檢查
資料裡不會出現這份文件沒有寫的行為鍵，也會檢查每一種行為至少有一隻真的怪在用。

## 2. 七種行為

### 2.1 ambush 伏擊

埋在地下裝成場景的一部分，玩家走進 `trigger_range` 才鑽出來。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `trigger_range` | 4.0 | 玩家走進這個距離就鑽出來，單位公尺 |
| `emerge_ms` | 500 | 鑽出來的動作時間，這段時間站著不能動也不能出手 |

- 埋伏中不閒晃、不索敵、不會被同伴喊話拉走，實體快照的 `hidden` 是 true。
  這個旗標會跟著 `entity.spawn` 送到客戶端，客戶端先不畫那一隻，收到 `monster_emerge` 才現身；
  不送的話破土特效會蓋在一隻本來就看得到的怪身上，伏擊就白做了。
- 鑽出來時發 `monster_emerge`，同時鎖定觸發的玩家。
- 死亡重生之後重新埋回去。
- 用的怪：枯枝樹精、空心枯樹。設計目的是讓森林的「樹」不能無腦穿過。

### 2.2 pack 成群

發現目標時對同群的同伴喊一聲，半徑內還沒有目標的同伴一起上。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `group` | 自己的怪物 id | 同一個 group 的才算同伴，跨物種成群靠它 |
| `radius` | 8.0 | 喊話半徑，公尺 |
| `cooldown_ms` | 8000 | 兩次喊話之間至少隔這麼久 |
| `max_join` | 3 | 一次最多叫來幾隻 |

- 發 `monster_shout`，事件帶 `joined` 真的加入的同伴 id，客戶端在喊的那一隻頭上冒一顆星。
- 不會叫醒埋伏中的怪、正在回家的怪、已經有目標的怪。
- `max_join` 是刻意的上限：沒有它的話一聲喊話可以把整張地圖的同族拉過來，走在路上會被無限滾雪球。
  精英怪和小 Boss 的半徑和上限都放大，這就是它們「危險」的地方。
- **被喊過來的怪自己不再喊**：一次拉怪只擴散一層。只限每次喊話的隻數還不夠，
  因為被叫來的那幾隻會各自再喊，兩三層之後整個營地連同精英怪都跟過來，那不是緊張是打不贏也跑不掉。
  記號放在 `monster_state.joined_by_shout`，放掉目標或回到出生點就清掉，下一次自己發現玩家時照樣喊得出來。
- 用的怪：枯骨兵系（group `bone`）、灰蝕狼、碎石鼠、峽谷禿鷲、洞窟蝠、空殼騎士（group `hollow`），
  以及對應的精英怪和小 Boss。

### 2.3 kite 拉開距離

遠程怪被貼身時往後退，退到最短距離外再繼續打。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `min_range` | 3.0 | 玩家比這個近就往後退 |
| `speed_percent` | 120 | 後退時的速度百分比 |

- 只影響移動，不影響鎖定；退到 `min_range` 加半公尺就停。
- 退路被牆擋住時就退不動，把遠程怪逼到牆角是正解。
- 用的怪：骨弓手、灰蝕巫骸、灰蝕巫長、峽谷鷲母、蝠巢母。

### 2.4 flee 逃跑

血量低於門檻就放掉目標往反方向跑。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `hp_percent` | 20 | 血量百分比低於等於這個值就跑 |
| `speed_percent` | 150 | 逃跑時的速度百分比 |
| `duration_ms` | 4000 | 跑多久 |
| `once` | true | true 時同一條命只逃一次，跑完就不再逃 |

- 發 `monster_flee`，逃跑期間不理任何人，時間到轉成回家，到家補滿血。
- 追不追是玩家的選擇：追得上就多一份經驗，追不上就浪費時間，這是刻意留的取捨。
- 用的怪：芽蜂、蕨葉蟲、碎石鼠、峽谷禿鷲、灰蝕頭狼。

### 2.5 cast 詠唱

有預告的範圍攻擊，預告期間可以被打斷，也可以走出圈外躲掉。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `skill_id` | 必填 | 傷害事件的 `skill_id`，表現層用它查特效 |
| `name` | 空 | 預告時浮在怪物頭上的招式名 |
| `element` | 怪物本身的屬性 | 傷害的攻擊屬性，走一般的屬性相剋 |
| `damage_type` | physical | physical 吃 ATK 和防禦，magic 吃 MATK 和魔防而且必中 |
| `center` | target | target 以預告當下玩家的位置為圓心，self 以怪物自己為圓心 |
| `range` | 7.0 | 目標在這個距離內才會開始詠唱 |
| `radius` | 2.5 | 圓的半徑 |
| `damage_percent` | 180 | 傷害倍率 |
| `telegraph_ms` | 1200 | 預告到落地的時間 |
| `cooldown_ms` | 9000 | 兩次之間的冷卻，被打斷也重新排冷卻 |
| `interruptible` | true | true 時受到任何傷害就中斷 |
| `knockback_m` | 0.0 | 落地時把命中的人推開幾公尺 |

- 開始詠唱發 `monster_cast_start`，帶圓心、半徑和落地時間；中斷發 `monster_cast_cancel`；
  落地發 `monster_cast_hit` 再逐一結算傷害。
- 圓心在預告當下就固定，所以「看到圈就走開」永遠有效，這是讀得懂的關鍵。
- `interruptible` 為 false 的招式只能靠走位躲，用在 Boss 的大招上。
- 用的怪：微光孢菇、腐朽行屍、灰蝕巫骸、露珠長者、峽谷鷲母、灰蝕骨長、蝠巢母、骨陣官、灰蝕骸冠的第二和第三階段。

### 2.5.1 預告型技能：形狀、方向、多段

2026-09-27 使用者：「王放技能要可以看到方向以及範圍 跟詠唱跳 我想做成有點需要操作的遊戲」。
`cast` 多寫 `shape` 或 `steps` 就是預告型技能，上表的欄位照樣有效，另外多這些：

| 欄位 | 預設 | 意思 |
|---|---|---|
| `shape` | circle | `circle` 圓、`fan` 扇形、`line` 直線、`ring` 環，不認得的當圓 |
| `aim` | target | 方向怎麼定：`target` 開始詠唱時從怪物看向目標，`facing` 怪物當時面向的方向 |
| `radius` | 2.5 | 圓、扇形、環的外半徑，0.2～30 |
| `inner_radius` | 外半徑一半 | 環中間安全的洞 |
| `angle_deg` | 90 | 扇形的全角，1～360 |
| `length`、`width` | 6、2 | 直線從原點往前的長度和總寬，長 0.2～40、寬 0.2～20 |
| `steps` | 無 | 多段依序，最多 12 段；每段可以寫自己的形狀和尺寸，沒寫的沿用這一層 |
| `steps[].offset` | [0, 0] | 這一段的錨點：從原點往前幾公尺、往右手邊幾公尺，前方就是鎖定的方向 |
| `steps[].delay_ms` | 0 | 詠唱結束後再過多久落下，0～10000 |
| `steps[].damage_percent`、`knockback_m` | 沿用上一層 | 這一段自己的倍率和擊退 |
| `hold` | 預告型是 true | 詠唱開始到最後一段落下前站著不動、不普攻、不轉身 |

```json
"cast": {"skill_id": "ember_sweep", "name": "焰掃", "element": "fire", "damage_type": "magic",
  "center": "self", "aim": "target", "shape": "fan", "radius": 7.0, "angle_deg": 100,
  "telegraph_ms": 1500, "cooldown_ms": 9000, "range": 7.0, "damage_percent": 220, "interruptible": false}
```

- 原點、方向、每一段的位置和落下時間在開始詠唱那一刻全部算好鎖死，之後目標怎麼跑、王被推到哪裡都不改。
  出處是 rAthena `src/map/unit.cpp` 的 `unit_skilluse_pos2`：地面技能開始詠唱時記下 `skillx`、`skilly`，施放者停下腳步；
  RO 是格子判定沒有方向，扇形、直線、環、多段是這裡加的，方向同樣開始時鎖死
- 判定只在落下那一刻：這一毫秒站在範圍裡才中，詠唱中一直在裡面、最後一刻離開就躲掉；邊線上算中；只看人站的點不看體型
- 落下的時間精確到毫秒，不等 200ms 一次的 AI；翻滾無敵窗是按下後 40 到 240 毫秒，落下時在窗裡就算閃掉
- 多段技能詠唱結束之後已經放出去，打不斷，王死了剩下的段才取消；`interruptible` 只管詠唱中
- 一隻王好幾招寫 `casts` 陣列：照清單順序挑第一招自己冷卻好了、目標在 `range` 內的；每招各自 `cooldown_ms`，
  `first_ms` 是出生後第一次能放的時間，沒寫就等一個冷卻；放完一招到下一招至少隔怪物最外層的 `cast_recover_ms`，預設 1500。
  階段可以寫 `casts` 整組換掉，換階段時新的招馬上能放
- 沒寫 `shape` 和 `steps` 的舊詠唱照舊：圓形、邊走邊唸
- 形狀和判定在 `src/core/combat_telegraph.gd`，測試在 `tests/test_server_telegraph.gd`，現在都是測試假資料，
  各王的正式招式數字由企劃填進 `data/monsters.json`

### 2.6 summon 召喚

叫出小怪一起打。

| 欄位 | 預設 | 意思 |
|---|---|---|
| `monster` | 必填 | 要叫出來的怪物 id，資料裡要存在 |
| `count` | 2 | 一次叫幾隻 |
| `radius` | 3.0 | 在自己周圍這個半徑內找可以走的落點 |
| `cooldown_ms` | 20000 | 兩次之間的冷卻 |
| `max_alive` | 4 | 自己叫出來的小怪同時最多幾隻 |

- 發 `monster_summon`，帶實際叫出來的小怪 id。
- 小怪不重生，死掉就從世界移除；主人死掉或離開地圖，還活著的小怪也一起消失。
- 小怪一出來就跟著主人的目標打。
- 用的怪：露珠母泡、空心枯樹、蝠巢母、灰蝕巫長、骨陣官、灰蝕骸冠。

### 2.7 phases 階段

Boss 和小 Boss 掉到血量門檻時換一套打法。

```json
"phases": [
  {"hp_percent": 70, "name": "碎裂", "move_speed": 2.8,
   "area_attack": {"radius": 5.0, "damage_percent": 170, "cooldown_ms": 8000, "telegraph_ms": 1100},
   "summon": {"monster": "bone_fragment", "count": 2, "radius": 4.0, "cooldown_ms": 24000, "max_alive": 4}},
  {"hp_percent": 40, "name": "召骨", "cast": { ... }}
]
```

| 欄位 | 意思 |
|---|---|
| `hp_percent` | 血量百分比低於等於這個值就進入這一段，由高到低排 |
| `name` | 階段名稱，發在事件裡給公告和特效用 |
| `move_speed` | 這一段之後的移動速度，不寫就不改 |
| `area_attack` | 換掉原本的範圍攻擊，欄位和怪物資料最外層的 `area_attack` 一樣 |
| `cast` | 換掉原本的詠唱，欄位同 2.5，換階段當下冷卻歸零，馬上放一次 |
| `casts` | 換掉原本的整組招，欄位同 2.5.1，換階段當下新的招馬上能放 |
| `summon` | 換掉原本的召喚，欄位同 2.6，換階段當下冷卻歸零 |

- 進入階段發 `monster_phase`，帶階段編號和名稱。
- 階段只前進不後退，補血也不會退回上一段；死亡重生時整組重設，速度也還原成資料檔的值。
- 用的怪：灰蝕骸冠三段、碎石霸主兩段、骨陣官兩段。

## 3. 巡邏

巡邏路線不寫在怪物資料裡，寫在地圖檔的出生點上，因為同一種怪在不同地圖要走不同的路。

```json
{"monster": "hollow_knight", "position": [1.5, 13.5],
 "patrol": [[1.5, 10.5], [1.5, 13.5], [1.5, 16.5], [-1.5, 13.5]]}
```

- 只有單隻的出生點可以寫，一群的不行；2 到 12 個點，每個點都要可以走，否則整張地圖驗證不過。
- 沒有目標時沿著點依序走，走到一個點停 1.2 秒再走下一個，走完回第一個點，形成循環。
- 被牆擋住走不動時直接跳到下一個點，不會卡死。
- 有巡邏路線的怪不閒晃；被拉走之後回家，回到出生點就接回巡邏。
- 用在每張地圖的一隻守衛，讓玩家在路上一定會遇到一隻會動的怪。

## 4. 事件一覽

客戶端收到的 `battle.event`，登記在 `src/world/skill_effects.gd` 的 `MONSTER_EVENT_LOOKS`，
換美術只要改那張表或在 `ART` 填圖檔，程式不用動。

| 事件 | 欄位 | 表現 |
|---|---|---|
| `monster_emerge` | entity, target, position, emerge_ms | 腳下一圈土色爆發 |
| `monster_shout` | entity, target, position, radius, joined | 頭上一顆會轉的星 |
| `monster_flee` | entity, target, until_ms, speed_percent | 頭上一道白光 |
| `monster_cast_start` | entity, skill_id, name, element, target, start_ms, end_ms, cast_ms, at_ms, direction, shape, areas, position, radius | 地上照 areas 畫預告，王頭上詠唱條；格式見下 |
| `monster_cast_cancel` | entity, skill_id, reason | 頭上浮「被打斷」 |
| `monster_cast_hit` | entity, skill_id, element, position, radius, area_index, area | 那一段炸開 |
| `monster_summon` | entity, monster_id, minions, position | 腳下一圈紫光 |
| `monster_phase` | entity, phase, name | 身上往上升的光環 |

`monster_cast_cancel` 的 `reason` 是 `damage` 被打斷、`target_lost` 目標不見、`dead` 自己死了。

`monster_cast_start` 給預告特效和詠唱條，時間都是伺服器毫秒，位置和方向是 `[x, z]`：
- `start_ms`、`end_ms`：詠唱開始和結束，詠唱條從這裡畫；`cast_ms` 是兩者的差；`at_ms` 等於 `end_ms`，舊欄位
- `direction`：鎖定的方向，單位向量；`shape`：只有一段時是那一段的形狀，多段是 `steps`
- `areas`：每一段 `{shape, position, direction, radius, inner_radius, angle_deg, length, width, at_ms}`，照落下順序；
  沒用到的尺寸是 0；`position` 是這一段的錨點：圓、環、扇形的圓心，直線的起點；`at_ms` 是這一段落下的時間
- `position`、`radius`：原點和蓋住所有段的圓，給還只會畫圓的客戶端，新的表現層看 `areas`
- 後進視野的人在 `entity.spawn` 的 `monster_cast` 拿到同一組欄位，`areas` 只剩還沒落下的，`time_ms` 是現在
- `monster_cast_hit` 每一段落下發一則，`area_index` 是第幾段，`area` 是那一段，欄位同上

實體快照另外多了三個欄位給表現層用：`hidden` 埋伏中、`elite` 精英怪、`phase` 已經進入第幾段。

## 5. 精英怪與小 Boss

兩種都是用怪物繼承做的，資料寫法在 `src/core/registry.gd` 的 `resolve_monsters`：

```json
"ash_wolf_alpha": {
  "name": "灰蝕頭狼",
  "base": "ash_wolf",
  "elite": true,
  "level": 12,
  "stat_multipliers": {"max_hp": 4.5, "atk": 1.5, "def": 1.2},
  "exp_multiplier": 3.5,
  "behavior": { ... },
  "drops": [ ... ]
}
```

- `base` 繼承另一隻怪的全部欄位，自己寫的欄位蓋過去；`stats` 和 `art` 是逐欄位合併，只改一兩個數字不會整段被覆蓋。
- `stat_multipliers` 乘在繼承來的 `stats` 上，`exp_multiplier` 乘在經驗上。
  好處是本體的數值被平衡調整時，精英怪和小 Boss 自動跟著調，不會變成兩套要各自維護的數字。
- `elite` 精英怪：血量約四到四點五倍、攻擊一點五倍、經驗三倍多，行為比本體多一種，掉落多一階。
- `mini_boss` 地區王：最低 30 級，`balance.json` 的 `boss_rules.min_level`；血量約同等級曲線的 20 倍、攻擊約 1.85 倍、經驗十倍，重生 60 分鐘，狀態和擊退免疫，必掉一樣王的信物；規則在 `docs/自有數值系統.md` 第 7.3 節。
- `minion` 召喚出來的小怪：血量是本體的四分之一到三分之一，不重生，沒有掉落。
- 三種變種的 `art` 都要自己的 `height`、`view_m`、`frame_px`，倍率規則見第 7 節；沿用本體的畫格會讓變種在畫面上和本體一樣大。
- 這三種都不進 `tests/test_world_maps.gd` 的同等級曲線檢查和練等節奏檢查，因為它們本來就刻意偏離曲線。

## 6. 掉落稀有度與首殺

- 掉落的每一項可以寫 `tier`：`common`、`uncommon`、`rare`、`epic`，只影響 `drop` 事件帶的顏色提示，
  機率仍然只看 `chance`。顏色表在 `skill_effects.gd` 的 `TIER_COLORS`。
- 掉落可以寫 `amount_max`，數量在 `amount` 到 `amount_max` 之間由伺服器擲，材料才不會每次都掉一個。
- 每一隻怪可以寫 `first_kill: {base_exp, job_exp}`，第一次打倒這一種怪多給一份經驗。只給經驗不給金幣，寫了 `gold` 也不理。
  紀錄存在角色資料的 `first_kills`，跟著存檔簽章；只給真的打倒的那個人，隊伍分經驗的人不會跟著拿。
  發 `first_kill` 事件，伺服器寫 `exp.first_kill` 稽核。
  設計目的是讓「換一張圖、遇到沒看過的怪」本身就有回報，鼓勵探索而不是只在一個點刷。

## 7. 畫格尺寸的規則

2026-09-16 訂。`data/monsters.json` 的 `art` 區塊裡有三個互相牽制的數字，寫錯會讓圖被切掉或讓變種白做：

| 欄位 | 意思 |
|---|---|
| `height` | 這隻怪在世界裡幾公尺高，`mpuppet.py` 照它把四視圖縮放 |
| `view_m` | 那一格由下到上涵蓋幾公尺。取景是正方形，所以是照模型最長的一邊算，蝸牛和蝙蝠比自己高得多 |
| `frame_px` | 一格幾像素。**這一格是推出來的，不要自己填**，算法見下面的密度政策 |

只有 `height` 和 `view_m` 是人決定的，`frame_px` 是算出來的。順序永遠是身高 → 取景 → 像素。

### 7.1 取景要裝得下自己

**規則：`view_m` 至少是 `height` 的 1.25 倍。**
多出來的空間留給跳躍、舉武器、揮擊這些會超出站立輪廓的動作。
`view_m` 小於 `height` 時那幾格會被切掉；而且變種沿用本體的 `view_m` 時，
產出來的圖和本體一樣大，長者、頭狼、鷲母、小 Boss 就白放大了。

**變種的做法：`height` 和 `view_m` 乘同一個倍率。**
這樣邊界留白的比例和本體一樣，畫面上真的看得出大一號。
現在的倍率：召喚出來的小怪 0.6～0.7，精英怪 1.35～1.4，小 Boss 2.0～2.2。

### 7.2 畫格像素照同一個密度算

**規則：`frame_px = 無條件進位到 64 的倍數(view_m × 112)`，夾在 128 到 384 之間。**

112 px/m 對上桌機鏡頭拉到最近時的 114 px/m，也就是最清楚的情況下一比一，
手機和一般鏡頭距離還有 1.6 到 1.8 倍的餘裕給 mipmap。
量測、記憶體帳和為什麼是 112 全部在 `docs/效能與記憶體.md` 的畫格尺寸政策那一節。

**上限那個 384 是暫時的，而且它不該是挑一個好看的整數，要由圖集排版推出來。**

一張圖集的像素數超過 12,582,912，那張地圖就要多付 64 MB 的配置器保留，
而且是那張地圖上最大的一份圖集說了算，不是加總。所以上限是算出來的：

```
一格最多幾像素 = 無條件捨去到 64 的倍數(sqrt(12582912 ÷ 格子數))
```

算式在 `src/dev/vram_report.gd` 的 `max_frame_px_for_layout`，那裡是唯一的來源：

| 圖集排版 | 格子數 | 上限 |
|---|---|---|
| 現在的固定 8 欄 × 25 列 | 200 | 192 |
| 緊密排 8 欄 × 17 列 | 136 | 256 |

**所以真正要動的是排版，不是畫格尺寸。**192 對 4.08 公尺的骨陣官只有 47 px/m，
和 112 px/m 的政策差太遠，不能接受；緊密排之後 256 才是又進預算又夠清楚的答案。
格式契約已經上線，寫在 `docs/精靈圖規格.md` 的「圖集排列」，引擎兩種排版都讀得動，
所以三個產圖管線可以各自照自己的進度換過來。

中間會先做一步：384 和 320 降到 256。那一步**是省記憶體不是進預算**，
因為 256 在今天的排版下還是 2048×6400 = 13.1 M 像素，仍然在線上。
七份要重算的清單在 `docs/效能與記憶體.md` 的「384 降到 256 要重算哪幾份」。
`tests/test_vram_budget.gd` 盯著這件事不會忘掉。

**兩條規則衝突時，密度政策贏。**
原本第 7.1 節寫「變種的 `frame_px` 也跟著乘同一個倍率」，現在不這樣做了：
`frame_px` 只看 `view_m`，而變種的 `view_m` 本來就乘過倍率，所以畫格自然會跟著變大，
只有碰到 128 下限和 384 上限時才會和本體一樣。
下限讓小怪不會小到貼圖過濾出問題，上限守住單張圖集的記憶體；
現在只有骨陣官（`view_m` 4.083）被上限夾到，密度 94 px/m。

改了 `view_m` 或 `frame_px` 之後，那一份圖集就要重算，不然遊戲照 meta 畫出來的大小和設計的不一樣。
`test_shipped_sheets_match_the_frame_data` 會比對 meta 和資料，對不上就直接失敗。
政策改版時 26 份舊圖集曾經列在 `STALE_SHEETS` 暫時略過，2026-09-16 全部重算完，
那個常數和略過都已經刪掉。之後再改取景就是當場重算，不要再加白名單。

四個檢查在 `tests/test_monster_art.gd`：
`test_every_monster_frame_fits_its_declared_height` 抓畫格裝不下自己的怪，
`test_every_monster_frame_px_follows_the_density_policy` 抓沒照密度算的 `frame_px`，
`test_variants_do_not_reuse_the_base_frame` 抓變種沿用本體取景的情況，
`test_shipped_sheets_match_the_frame_data` 抓資料改了圖卻沒重算的情況，錯誤訊息都會直接說要改哪一個欄位。

## 8. 平衡與可讀性的原則

1. 每一種行為都要有一個玩家看得到的訊號：圈、星星、破土、光環，看不到的行為等於沒有。
2. 每一種行為都要有一個對策：走出圈、打斷、先殺會喊人的、把遠程逼到牆角、追或不追。
3. 行為只影響「怎麼打」，不影響「打得動打不動」，數值全部走 `docs/自有數值系統.md` 的曲線。
4. 成群和召喚都有上限，任何一個技能或位置失誤都不會滾成無法收拾的局面。
5. 資料寫錯時失敗要安靜而明確：找不到的召喚物略過、巡邏點不能走整張地圖驗證不過、未知的行為鍵測試會抓到。
