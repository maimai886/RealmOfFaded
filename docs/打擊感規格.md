# 打擊感規格

戰鬥表現的時間契約：伺服器事件、客戶端預測、角色顯示三方都照這份走。舊專案的量測過程和完整推導在 `../Sproutia/docs/打擊感規格.md`。

使用者說過的：

- 2026-09-15「打擊感不順暢，很慢然後很僵」；同一天嫌傷害數字太大，已經調小，不能調回去
- 2026-09-16「玩起來操作感很鳥，沒有流暢感」「移動 躲避 動作 感覺起來就是很死」，之後改成動作遊戲方向：方向鍵直接操作是主要玩法，點地是輔助，加上有無敵幀的閃避翻滾
- 2026-09-16「怪物移動不順暢動畫不順暢」「戰鬥打擊感弱」
- 2026-09-16 指定研究《夢之形》和《靈谷 SpiritVale》，結論在第 7 節

## 1. 時間軸

時間都是伺服器毫秒，客戶端用估計的時鐘差換算。攻速公式和數字在 `data/balance.json` 的 `attack_speed`，說明在 `docs/自有數值系統.md`；1 級初心者 amotion 580、adelay 1159 毫秒。

| 時刻 | 伺服器 | 客戶端 |
|---|---|---|
| 點擊 | 收到 `act.attack`，下一個 tick 鎖定目標 | 目標在距離內、不在攻擊間隔、沒在詠唱時，這一幀就轉向目標開始揮；命中格排在「伺服器會處理這則指令的 tick 加 amotion」 |
| T0 出手 | tick 邊界算好命中和傷害，發 `attack_start`，下一擊排在 T0 + adelay | 已經先揮的那一下接手不重播，否則收到就揮；攻擊者瞬間轉向 |
| T0 + amotion | 扣血、硬直，發 `damage` | 收到就播，傷害數字、閃白、停頓、擊退、火花、音效、血條全部同一幀 |
| 命中之後 | | 收招 amotion × 0.25 後回站立，中途移動直接打斷收招 |
| 預測失敗 | 回 ok=false，或過了套用 tick 加 250 毫秒還沒有 `attack_start` | 動作收回站立 |

- 傷害、暴擊、HP、冷卻永遠由伺服器決定，預測只改畫面
- 只有 `respawn` 和掉落物出現消失要排到內插時間播，其他戰鬥事件收到就播；自己被打也一樣
- 自動攻擊關掉時，揮擊一開始就送 `act.stop`，這一下照樣打到
- 命中那一段從聲音到火花必須是連續的程式碼，中間不准有等待、tween、計時器或延後呼叫；聲音和停頓用同一組 `crit`、`heavy` 旗標判級別。差幾幀出現打擊感就變軟

## 2. 命中回饋

這些數字搬到 Rust 時放 `data/*.json`，調手感不用重編。

| 效果 | 數值 |
|---|---|
| 受擊方停頓 | 一般 40 毫秒、傷害超過 HP 上限 25% 算重擊 60、暴擊 80；不超過攻擊方 amotion 的 12% |
| 攻擊方停頓 | 受擊方的一半，一般最多 25、暴擊最多 40 |
| 閃白 | 50 毫秒 |
| 擊退位移 | 0.24 公尺，暴擊 1.6 倍，150 毫秒彈回，只動顯示位置 |
| 畫面震動 | trauma 一般 0.35、暴擊 0.58，震幅取 trauma 平方，最大角度 1.2、1.2、2.4 度，每秒衰減 2.6；雜訊輸出約正負 0.65 要除回正負 1，每秒抖約 11.6 下；一般命中畫面位移約 2 到 4 像素、暴擊約 8 |
| 傷害數字 | 0.1 秒放大到 1.2 倍，0.7 秒上飄淡出 |

停頓只停當事人的動畫，不動全域時間。震動的基底 trauma 太小平方之後就看不見，舊專案 0.1 時畫面只動 0.12 像素。

## 3. 移動

- 伺服器只在 tick 邊界套用移動指令；客戶端把指令排在伺服器會開始走的那個 tick 才動位置，算法在 `docs/伺服器架構.md` 第 0 節。面向和走路動作在按下那一幀就有，位置最多晚一個 tick
- 收到自己的伺服器位置時，和那個 tick 對應的本機時間的預測位置比：0.02 公尺內不理，0.12 內每次修 15%，超過 0.12 在 150 毫秒內拉回，超過 4 公尺直接換；兩邊都停著時 0.35 內一次對齊
- 校正門檻 0.12 不能調大來蓋問題，tick 估錯一格就會有 0.175 公尺側向誤差
- 移動指令至少隔 50 毫秒，從走切到停立刻送
- 攻擊鎖定時自己的位置跟伺服器快照走，不預測
- 別人內插延遲 60 毫秒，超過最新快照用速度外推最多 100 毫秒；接遠端伺服器後要重量抖動再定
- 帶 Alt、Ctrl、Cmd 的按鍵不算移動；介面元件有鍵盤焦點時方向鍵不動角色
- 碰撞只用方形不用圓形：沿方形邊滑動和步長無關，伺服器一 tick 一步、客戶端一幀一步走出同一條路；圓形的法線一路在轉會分岔超過門檻。擦過方形角落在 6 公尺邊長時最多 0.048，出現遠大於 6 公尺的方形要重量

**詠唱中不能走**，2026-09-17 定。移動指令整個拒絕，原因 `casting`，人不動、詠唱照跑；放開方向鍵的停止照收。只有閃避翻滾能打斷，另外受傷、冰凍、暈眩、新的攻擊指令照舊打斷。判斷用「還有剩餘詠唱時間」，瞬發技不受影響，怪物的詠唱是另一套。畫面上一個字都不跳，客戶端詠唱中不送移動也不預測，詠唱一結束還按著方向鍵的下一幀就起步。

**移動取消出手**：出手還沒結算時移動或閃避，那一下的傷害不算並發 `attack_cancel`，下一次出手只會往後推不會提前，所以取消永遠只有代價。出手後按方向鍵下一個 tick 就動，舊版要等整段 amotion。怪物刻意不套用，牠們的出手要有承諾玩家才有東西可以閃。

## 4. 角色顯示

- 走路播放倍率 = 顯示速度 ÷ 參考速度，夾在 0.55 到 2.6；玩家參考速度 1.7，怪物用牠自己的 `move_speed`，因為圖集照牠自己的步調畫。固定參考速度會讓快的怪被夾住，腳跟不上身體就是滑步
- 起步那一幀顯示速度直接跳到目標的 70%，再用 0.05 秒補滿；放開用 0.07 秒收回站立。位置照樣按下就走、放開就停
- 精靈圖方向直接切換不平滑，RO 也是這樣
- 受擊動作只在沒播別的單次動作時播；停頓中顯示位置小幅抖動，判定位置不動
- 單次動作要把命中格對齊到伺服器的 amotion，圖集有標命中格就用它

## 5. 閃避翻滾

伺服器是唯一判斷無敵的地方，客戶端只送方向。數字在 `data/balance.json` 的 `dodge`：起步 40 毫秒還打得到，之後 200 毫秒無敵，300 毫秒內位移 2.4 公尺，收招 120 毫秒，冷卻 900 毫秒從按下起算、跟著角色換地圖和重登。

- 無敵窗故意比位移短、遠短於冷卻：怪物預警 900 到 1600 毫秒來得及反應，但連灌閃避只有約 22% 時間無敵
- 出手中可以閃，還沒結算的那一下丟掉；詠唱中閃避打斷詠唱，原因 `dodge`；坐著閃避會站起來
- 冰凍、暈眩回 `disabled`，被絆住回 `rooted`，死亡回 `dead`；閃避會解除攻擊鎖定
- 電腦空白鍵，往按住的方向，沒按就往面向；按住不連滾。手機是攻擊鈕旁的閃避鈕，不能和技能鈕疊在一起
- 動作不自己帶位移，位置由預測照伺服器規則推；鎖定目標時維持面向敵人。圖集沒有 `dodge` 動作時拿走路快轉加一個身高 6% 的小跳頂著
- 預測和移動同一套：按下那一幀播動作，位置排到伺服器會處理的 tick 才滾；客戶端自己記冷卻只擋明顯按太快的

## 6. 鏡頭

位置跟隨照 Shooter 的 `Camera2D` 平滑：`lerp(目前, 角色, clamp(速度 × dt, 0, 1))`，移動時略落後、停下平滑歸位，不做預看也不鎖死。數字在 `data/camera.json`。

## 7. 參考作品

**夢之形**是手感的正面範本：一邊移動一邊普攻、移動方向和瞄準方向分開、技能用瞄的、閃避是核心而且接普攻是輸出手段；玩家點名「施放前要定身」是爛設計。**靈谷**負評大多罵伺服器，戰鬥唯一的抱怨是「怪物實際座標和看到的不一致」，那正是內插做不好，給我們的是反面教材。

已經做到的：移動取消出手、有無敵幀的閃避、命中回饋同一幀、怪物有可閃的預警、內插 60 毫秒。

**還要使用者決定的三件事**，實作的人不要自己動手：

1. **詠唱時間**：13 招有詠唱，滿級火箭 3.2 秒、雷球 3.8 秒，而且詠唱隨等級變長，技能練越強越難用。選項是縮短數字、詠唱中可以慢走、改瞬發加冷卻；建議先縮數字
2. **移動和面向分開**：往側面走、對前方打。要在 `entity.state` 加面向並同步，精靈圖照新面向取圖，不動技能資料；投資報酬最高
3. **瞄準式技能**：鎖定目標和指定地面改成朝方向射，技能資料、命中判定、預測、怪物閃躲、特效方向全部要改；成本最大，好處也最大
