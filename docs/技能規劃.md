# 技能規劃

2026-09-16 整理。每個職業路線的完整技能表、數值出處、資料欄位和引擎規則。技能的倍率和冷卻是照 RO Renewal 的 rAthena 資料改編，
改編的地方寫明理由。資料在 `data/skills.json`，邏輯在 `src/core/battle_world.gd`、`src/core/skill_combat.gd`，
事件契約在 `docs/伺服器架構.md` 第 9 節。

**技能倍率乘進去的那個底層公式已經換掉了。** 傷害、命中、減傷、屬性相剋、詠唱時間從 2026-09-16 起改成 ROF 自己的一套，
規格在 `docs/自有數值系統.md`，常數在 `data/balance.json`。這份文件裡提到的 DEF 減傷、`HIT − FLEE`、`sqrt(530)` 詠唱都已經作廢。
屬性收成九種：`neutral` 無屬性、`fire` 火、`water` 水、`wind` 風、`earth` 土、`light` 光、`dark` 暗、`time` 時間、`space` 空間。
念屬性的技能改成無屬性；`time` 的技能打中會疊遲滯，`space` 的技能無視三成防禦而且會推開目標，規則在 `docs/自有數值系統.md` 第 3.2 節。

## 1. 換算規則

| 項目 | RO | ROF |
|---|---|---|
| 距離 | 格 | 1 格 = 0.75 公尺，`data/skills.json` 的 `cell_meters` |
| 範圍 | n×n 格 | 半徑 = (n−1)/2 格，例如 5×5 是半徑 1.5 公尺；隕星雨、暴風雪、雷霆審判的範圍縮成 2.25 公尺，手機畫面上 9×9 格太大 |
| 詠唱 | 變動詠唱 + 固定詠唱 | `cast_ms` 是變動詠唱，照 DEX×2+INT 縮短，`fixed_cast_ms` 不縮短，`SkillCombat.cast_time_ms` |
| 攻速加成 | ASPD 點數 | `bonus.aspd_fixed`、`aspd_percent`，接 `Formulas.player_attack_delay`，說明在 `docs/打擊感規格.md` |
| 傷害 | ATK 或 MATK × 倍率 | `damage_percent` 每段倍率，物理照普攻的 DEF 公式，魔法照 MDEF 公式，misc 照 `misc_formula` |
| 狀態時間 | Duration2 | `status_duration_ms`，Boss 一律免疫，不死系免疫冰凍和戰吼 |

## 2.05 這條路線的技能樹為什麼長這樣

2026-09-17 使用者把職業等級上限拉到一轉 50、二轉 70 之後，技能點變成 153 點，
遠超過原本的技能樹裝得下的量。使用者決定**把技能樹加大**而不是降低給點速度，
目標是「買得起大約七成」，玩家得取捨而不是everything全點滿。

加大的原則是**每個新技能都要和既有的拉不同方向**，不是同一件事再多一點：

- **信徒本來一面倒是支援**，六個技能裡只有晨曦之光在輸出。加的四個把樹拉成兩條：
  爐擊和灼蝕是「打」，聖域是「控住一塊地」，守夜式是「站定不動換防禦」。
  守夜式的移動速度 −30% 是真的代價，不是裝飾：信徒要站在隊伍中間，釘住自己是有風險的決定
- **神職者加的八個排成三組二選一**：曦矛（單體爆發、長詠唱）對晨曦裁決（範圍）、
  曦佑（攻速暴擊）對晨誓（攻擊力命中）和護誓（擋硬直）、庇護所（壓低敵人攻擊）對曦盾詠唱（拉高我方防禦）。
  醒鐘是解厄的隊伍版、曦行是全隊位移、殘光是短時間把治療推到極限的救火鈕
- **前置接得出分支**：技能視窗是照 `requires` 畫的，所以曦盾詠唱底下掛庇護所和曦行、
  晨曦裁決底下掛曦矛和祛蝕，視窗上看得出來是一個選擇而不是一張清單

灼蝕第一版是 0.4 秒後延遲、沒有冷卻，量出來每秒傷害接近術士念波衝擊的兩倍，
等於支援職壓過施法職。改成 0.8 秒後延遲、傷害壓低之後，它的定位回到
「我得隨時準備補人，所以要一個不用詠唱的攻擊」，不是輸出選項。

## 2.1 信徒與神職者的算法是自己的

支援職最容易變成「把 RO 的牧師抄過來」，所以這一條路線特別寫清楚哪裡不一樣：

- **治療吃 MATK。** 我們的式子是 `技能底數 + MATK × heal_matk_percent%`，再乘施放者的 `heal_power_percent`
  和目標的 `heal_received_percent`，實作在 `src/core/grace.gd`。
  RO 的治癒術是 `(BaseLv + INT) / 5 × (30 + 10 × 技能等級)`，完全不看 MATK 也不看裝備，
  所以 RO 的牧師換武器對治療毫無影響。我們讓提爐同時是攻擊和治療的來源，
  加在 INT 上的點兩邊都吃得到，支援職不用養兩套身材，撿到好提爐也和其他職業撿到好武器一樣有感。
- **減傷走比例曲線，不是吸收護盾。** 守禱和曦盾詠唱加的是 `def_percent` 和 `mdef_percent`，
  接的是 `docs/自有數值系統.md` 第 2.2 節的 `總防 / (總防 + K)`，而 `K = 50 + 10 × 攻擊方等級`。
  同一條增益對同等級的敵人有感、對高等級的敵人自然變弱，不會像 RO 的庇護那樣是一個和敵人強度無關的固定吸收值。
- **解除狀態是一個技能加一張資料表。** `cleanse` 區塊寫得下哪些 kind，等級資料寫一次解幾個。
  RO 拆成治癒、狀態恢復、天使之塵好幾個技能各解一種；我們只有解厄一個，能解什麼由資料決定。
  在這之前全遊戲沒有任何提早解除狀態的辦法，只能等時間到，所以這是信徒在隊伍裡最難被取代的一件事。
- **增益掛得到別人身上。** 全遊戲只有這條路線能把增益掛在同伴身上，其他職業的 `self_buff` 只作用在自己。
- **攻擊屬性是光。** 晨曦之光和晨曦裁決是光屬性，打暗屬性 175%、打其他一律 100%。
  灰蝕地窟的怪都是暗屬性，所以這條路線的傷害只有在那裡才追得上巫師，在草原上永遠是中下段。
  這是刻意的取捨，不是沒調好。

## 3. 和 RO 不同的地方

- 陷阱沒有陷阱道具，改用「同時最多 3 個、不能疊放」限制洗頻
- 火牆的推開方向固定是牆的法線往施放者對面，RO 是照目標背後
- 隕星雨、暴風雪、雷霆審判的範圍縮成 2.25 公尺，隕石的散布和落點半徑縮成 1.5 公尺，手機畫面比例
- 雷霆審判把總倍率拆成 4 波，RO 是一次 20 段
- 暴風雪冰凍照 Renewal 每波擲骰，被下一波打到就解凍再擲
- 戰意加速用 `aspd_fixed: 7`，對應 Renewal 的固定 +7 ASPD，Pre-renewal 的 +30% 不採用
- 鷹眼的射程每級 +0.5 公尺，RO 是 +1 格
- 冰凍中 DEF 減半、防禦屬性變水 1 級，受到任何傷害就解凍，rAthena status_damage
- 反擊架式擋下的是「近身」普攻：攻擊者離目標不超過目標普攻距離 + 0.75 公尺，而且攻擊者本身是近戰

## 4. 資料欄位

技能層級：
| 欄位 | 意義 |
|---|---|
| type | passive、self_buff、active_target、active_ground |
| damage_type | physical、magic、misc；misc 用 misc_formula，trap 或 falcon |
| no_damage | true 時不算傷害，只附加狀態，戰吼、泥沼、絆索 |
| ignore_flee | 物理技能必中 |
| hits_by_size | 段數依目標體型 |
| hit_interval_ms | 多段之間隔多久，沒寫同時到 |
| weapon_types | 熟練度只在拿這些武器時生效，武器種類是 items.json 的 weapon_type |
| requires | 前置技能等級 |
| tree | 技能視窗裡要放哪一格 `{"column": 2, "row": 1}`，不寫就照 requires 自己算，見第 7 節 |
| area_center、aoe_radius | 範圍中心 self、target、ground 和半徑 |
| knockback_m | 擊退公尺，等級資料可以覆蓋 |
| status | 命中後附加的狀態：id、kind、immune_boss、immune_elements、aggro、level_diff_chance、agi_reduces、linger_ms |
| ground | 地面物件：kind wall、trap、zone、meteor；cells、cell_radius、hit_interval_ms、trigger_radius、splash_radius、radius、interval_ms、waves、spread_m、max_active、replace_oldest、no_overlap_m、knockback_m、knockback_random、knockback_immune_elements |
| counter | 反擊的 damage_percent、hit_rate_percent、crit |
| auto_proc | 普攻命中自動發動：chance luk、delay_ms |
| revive | 有這個區塊就是復活術，目標只能是倒下的同伴，不能是自己；hp_percent 是沒寫等級資料時的預設比例 |
| targets | self、enemy、ally、dead_ally。ally 的技能打的是同隊活著的玩家，治療、解狀態、掛增益都落在目標身上 |
| exclude_self | targets 是 ally 時不能對自己放 |
| cleanse | 解狀態：`kinds` 是解得掉的 kind 清單，`max_count` 是一次最多解幾個，等級資料的 cleanse_count 優先 |
| requires_buff | 身上要有這個 status_id 的增益才放得出來，自己放的增益就是技能 id，例如曦破寫 `gather_breath`；沒有時原因 `no_buff`，詠唱中到期或被解掉也用這個原因取消，什麼都不扣 |
| consumes_buff | 放出去時把身上這個 status_id 的增益收掉，buff_end 的原因是 `consumed`；通常和 requires_buff 寫同一個。傷害在收掉之前就算好，被吃掉的增益這一擊還算得到 |
| self_debuff | 放出去之後對自己掛的減益：`id` 狀態名稱，不寫就是技能 id；`kind` 預設 debuff；`duration_ms`、`bonus` 是預設值，等級資料的 self_debuff_ms、self_debuff_bonus 優先；`cleansable` 不寫就是同伴解不掉，照 RO 阿修羅霸凰拳放完的後遺症 |

等級層級：sp_cost、cast_ms、fixed_cast_ms、after_cast_delay_ms、cooldown_ms、damage_percent、edge_damage_percent、hits、
hit_rate_percent、heal、heal_matk_percent、cleanse_count、duration_ms、bonus、knockback_m、aoe_radius、
status_chance_percent、status_duration_ms、status_bonus、status_bonus_monster、ground_lifetime_ms、ground_hits、
ground_count、revive_hp_percent、revive_sp_percent、self_debuff_ms、self_debuff_bonus。

曦破這種招寫法：

```json
"requires_buff": "gather_breath",
"consumes_buff": "gather_breath",
"self_debuff": {"duration_ms": 3000, "bonus": {"def_percent": -30}}
```

補自己的技能怎麼跑：`type` 是 self_buff 而且等級資料有 heal 或 heal_matk_percent 的，和撫傷走同一條治療，
治療加成、受治療加成、補回彩度都算，挑了屬性照 `data/element_effects.json` 的 support_effects 換附帶效果。
調息、療誓要給挑色就在資料寫 colour_slots 和 colour_elements，程式不用改。
打怪順便回血的，像爐擊，屬性已經用在傷害上，只回等級資料的 heal 固定量。

打同伴的技能怎麼跑：`battle_world._apply_support` 對每個目標依序做治療、解狀態、掛增益。
單體的目標由 `targets: ally` 選一個活著的同隊玩家；`type` 是 `active_ground` 而 `area_center` 是 `self` 時，
範圍內所有同隊玩家都算，施放者自己也在內。數值公式在 `src/core/grace.gd`，程式不認職業 id。

bonus 和 status_bonus 的鍵：atk、matk、def、mdef、hit、flee、dex、attack_range、agi_percent、dex_percent、atk_percent、
def_percent、hit_percent、flee_percent、aspd_fixed、aspd_percent、cri、move_speed_percent、no_flinch_hits、counter_hits、
matk_percent、mdef_percent、no_move、atk_vs_<種族>、hp_regen、sp_regen、hp_regen_max_hp_permille、
sp_regen_max_sp_permille、potion_hp_percent、potion_sp_percent、fire_damage_percent、
heal_power_percent 自己放出去的治療、heal_received_percent 自己收到的治療。

## 5. 引擎規則

- 狀態和增益都放在實體的 `buffs` 字典，key 是 status_id，自己放的增益 status_id 等於技能 id；kind 是 buff、debuff、freeze、stun、snare
- 冰凍和暈眩不能攻擊和施法，冰凍、暈眩、絆住和反擊架式不能移動；狀態附加時會打斷詠唱
- 怪物的數值從 `base_stats` 重算，百分比加成走 `SkillCombat.apply_stat_bonus`；玩家走 `character_data.combat_stats`
- 地面物件每個 tick 在移動之後處理，踩進陷阱的那個 tick 就觸發；施放者離開地圖時它放的東西一起收掉
- 火牆每格有自己的次數，同一個敵人每 100 毫秒最多被打一下；範圍效果第一波在放下之後 interval_ms 才來
- 隕石每顆是一個地面物件，`fire_ms` 到了才落下並炸半徑內的敵人，落下時間對齊 50 毫秒的 tick
- 陷阱只有敵人會踩，同一個人最多 3 個，和其他陷阱距離不到 0.75 公尺放不下
- 自動發動的獵鷹在普攻判定之後才擲骰，同種子結果可以重現，不扣 SP 也不看冷卻
- 普攻命中回血的 heal 事件，skill_id 是實際給 hit_hp_permille 的技能：學過的被動和身上的增益裡數值最大的那一顆，劍侍是息劍、行者是曦息
- requires_buff 在按下去和放出來的那一刻各驗一次；consumes_buff 和 self_debuff 在放出來的那一刻結算，中途取消什麼都不扣

## 6. 轉職

- 初心者職業 10 級加基本技能 9 級、考過轉職考試轉一轉，考試見 `docs/轉職考試.md`；一轉職業 30 級轉二轉；二轉職業 40 級轉三轉，都由四位導師的對話 `job_change:<職業>` 觸發，伺服器用 `JobChange.can_change` 再驗一次；
  每個一轉分成兩條二轉、每個二轉各接一個三轉，二十一個職業的表在 `docs/職業路線圖.md`，新職業的技能規劃在 `docs/技能與流派.md`
  - 門檻的真正來源是 `data/balance.json` 的 `levels.job_change_level`。2026-09-17 修正：
    三位舊導師的對話本來寫 40 級，比伺服器真正驗的 30 級嚴，玩家會被選項擋在門外卻查不出原因，四條路線現在統一是 30
  - 一轉上限 2026-09-17 改成 50，所以門檻 30 是「一轉走到六成就可以轉」。
    留在一轉練到 50 只多拿 24 點技能點，而技能點本來就已經多到花不完，所以現在沒有理由不早轉；
    之後如果把給點速度降下來，這個門檻就會變成一個真的要想的選擇
- 轉職後職業等級歸 1、職業經驗歸 0，技能和技能點全部保留，新分頁的技能開放學習，照 RO
- 對話選項有 `condition`，初心者看不到二轉選項，一轉看不到一轉選項，術士到劍侍導師那裡也看不到聖劍士
- 四位導師：劍侍導師 蓋爾、術士導師 露娜、斥候導師 芬恩、信徒導師 薇恩，全部在晨曦鎮南側排成一列

## 7. 技能視窗

`src/ui/skills_window.gd` 的分頁就是角色走過的職業，用 `SkillTree.job_route` 從 `jobs.json` 的 `next_jobs` 反推：
初心者只有一頁，轉職之後才多一頁，分頁名字是真的職業名字。不放「一轉職業」這種還沒發生的分頁，
遊戲不預告玩家還沒走到的路，見 `docs/決策紀錄.md`。

版面由 `src/ui/skill_tree_layout.gd` 從 `requires` 算出來，畫在 `src/ui/skill_tree_view.gd`：

- 同職業沒有前置的技能排第一列，有前置的排在最深的那個前置下面一列，父技能對齊子技能中間
- 一個技能只掛在第一個同職業前置底下，其他前置照樣拉線，例如迴旋斬三條線都畫得出來
- 前置在別的職業時不拉線，那個技能自己當一棵樹的根，例如雷球的前置在術士頁；提示框裡照樣列出前置和夠不夠
- 一排最多 `MAX_COLUMNS` 格，放不下的另起一排，視窗才不會橫著長出去
- 線上寫著要練到幾級才開得出來，前置滿了的線亮起來，沒滿的暗著
- 前置不夠的技能整格褪色但看得到，現在學得起來的外面圈一圈金線、加號換成主要按鈕
- 真的需要手排位置時在 `data/skills.json` 寫 `tree` 欄位，不要改程式

技能加進資料就會自己出現在樹上，位置不用人工維護。
