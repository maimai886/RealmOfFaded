# 技能規劃

技能資料的欄位、引擎規則和技能視窗的規則。技能數值全部在 `data/skills.json`，
技能樹、核心機制和還沒做的技能在 `docs/技能與流派.md`，傷害、命中、減傷、詠唱公式在 `docs/自有數值系統.md`，常數在 `data/balance.json`。
技能的倍率和冷卻以 RO Renewal 的 rAthena 資料為起點改編，每個技能的出處寫在它的 `source`。

## 1. 換算規則

- 距離：RO 的 1 格是 0.75 公尺，`data/skills.json` 的 `cell_meters`。
- 範圍：RO 的 n×n 格換成半徑 (n−1)/2 格；大範圍法術縮到 2.25 公尺，手機畫面上 9×9 格太大。
- 詠唱：`cast_ms` 是變動詠唱，會被屬性縮短；`fixed_cast_ms` 不縮短。
- 攻速加成用 `bonus.aspd_fixed` 和 `aspd_percent`。
- 傷害：`damage_percent` 是每段倍率，物理、魔法、misc 各走自己的公式。

## 2. 支援職的算法是自己的

不抄 RO 的牧師：

- 治療吃 MATK：`技能底數 + MATK × heal_matk_percent%`，再乘施放者的 `heal_power_percent` 和目標的 `heal_received_percent`。提爐同時是攻擊和治療的來源，支援職不用養兩套身材。
- 減傷走比例曲線不是吸收護盾：增益加的是 `def_percent`、`mdef_percent`，接 `docs/自有數值系統.md` 第 2.2 節的曲線，對高等級敵人自然變弱。
- 解除狀態是一個技能加一張資料表：`cleanse` 寫解得掉哪些 kind，等級資料寫一次解幾個；這是信線在隊伍裡最難被取代的事。
- 只有信線能把增益掛在同伴身上，其他職業的 `self_buff` 只作用在自己。
- 信線固定屬性是光，只在暗屬性怪多的灰蝕地窟追得上巫師，這是刻意的取捨。

## 3. 資料裡的舊樹和 RO 不同的地方

聖劍士、巫師、獵人還是 RO 骨架的舊樹，會照 `docs/技能與流派.md` 整批換掉，換之前照這幾條：

- 陷阱沒有陷阱道具，改用同時最多 3 個、不能疊放限制洗頻。
- 隕星雨、暴風雪、雷霆審判範圍縮成 2.25 公尺，隕石散布縮成 1.5 公尺；雷霆審判拆成 4 波。
- 暴風雪冰凍照 Renewal 每波擲骰，被下一波打到就解凍再擲。
- 戰意加速用固定 +7 攻速點數，不用 Pre-renewal 的 +30%。
- 冰凍中 DEF 減半、防禦屬性變水 1 級，受到任何傷害就解凍。
- 反擊架式只擋近身普攻：攻擊者是近戰，而且距離不超過目標普攻距離加 0.75 公尺。
- 復活術不燒藍色寶石，改用 SP 和長預備當代價；程式只看技能的 `revive` 區塊，不看職業。

## 4. 資料欄位

技能層級：

| 欄位 | 意義 |
|---|---|
| type | passive、self_buff、active_target、active_ground |
| damage_type | physical、magic、misc；misc 用 misc_formula |
| no_damage | 不算傷害，只附加狀態 |
| ignore_flee | 物理技能必中 |
| hits_by_size | 段數依目標體型 |
| hit_interval_ms | 多段之間的間隔，沒寫就同時到 |
| weapon_types | 熟練只在拿這些武器時生效，武器種類是 items.json 的 weapon_type |
| requires | 前置技能等級 |
| tree | 技能視窗手排位置 `{"column", "row"}`，不寫就照 requires 算 |
| area_center、aoe_radius | 範圍中心 self、target、ground 和半徑 |
| knockback_m | 擊退公尺，等級資料可以覆蓋 |
| status | 命中後附加的狀態：id、kind、immune_boss、immune_elements、aggro、level_diff_chance、agi_reduces、linger_ms |
| ground | 地面物件：kind wall、trap、zone、meteor，加 cells、cell_radius、hit_interval_ms、trigger_radius、splash_radius、radius、interval_ms、waves、spread_m、max_active、replace_oldest、no_overlap_m、knockback_m、knockback_random、knockback_immune_elements |
| counter | 反擊的 damage_percent、hit_rate_percent、crit |
| auto_proc | 普攻命中自動發動：chance、delay_ms |
| revive | 復活術，目標只能是倒下的同伴，不能是自己 |
| targets | self、enemy、ally、dead_ally；ally 打同隊活著的玩家 |
| exclude_self | targets 是 ally 時不能對自己放 |
| cleanse | `kinds` 解得掉的狀態，`max_count` 一次最多幾個，等級資料的 cleanse_count 優先 |
| requires_buff | 身上要有這個增益才放得出來，沒有時原因 `no_buff`，詠唱中到期或被解掉也用這個原因取消，什麼都不扣 |
| consumes_buff | 放出去時收掉這個增益，buff_end 原因 `consumed`；傷害在收掉之前算好 |
| self_debuff | 放完對自己掛的減益：`id`、`kind`、`duration_ms`、`bonus`、`cleansable`，不寫 cleansable 就是同伴解不掉 |

## 5. 引擎規則

- 狀態和增益放在實體的 `buffs`，key 是 status_id，自己放的增益 status_id 等於技能 id；kind 有 buff、debuff、freeze、stun、snare。
- 冰凍和暈眩不能攻擊和施法；冰凍、暈眩、絆住和反擊架式不能移動；附加狀態會打斷詠唱。
- 地面物件每個 tick 在移動之後處理，踩進陷阱那個 tick 就觸發；同一個敵人每 100 毫秒最多被同一塊打一下；第一波在放下之後 interval_ms 才來；施放者離開地圖就一起收掉。
- 陷阱只有敵人會踩，和其他陷阱距離不到 0.75 公尺放不下。
- 自動發動在普攻判定之後擲骰，同種子結果可以重現，不扣 SP 也不看冷卻。
- 補自己的 self_buff 如果等級資料有 heal，和撫傷走同一條治療，治療加成和挑色的附帶效果都算；挑色寫 `colour_slots` 和 `colour_elements`。打怪順便回血的只回固定 heal。
- 打同伴的技能對每個目標依序做治療、解狀態、掛增益；`active_ground` 加 `area_center: self` 時範圍內同隊玩家都算，自己也算。程式不認職業 id。
- 普攻命中回血只取學過的被動和身上增益裡數值最大的那一顆。
- requires_buff 在按下和放出時各驗一次；consumes_buff 和 self_debuff 在放出時結算，中途取消什麼都不扣。

## 6. 轉職和技能視窗

- 轉職後職業等級歸 1、職業經驗歸 0，技能和技能點全部保留，新職業的技能開放學習，照 RO。
- 技能視窗的分頁就是角色走過的職業，從 `next_jobs` 反推；不放還沒走到的職業分頁，遊戲不預告玩家還沒走到的路。
- 版面從 `requires` 自動算，技能加進資料就自己上樹，要手排才寫 `tree`：沒有前置的排第一列，有前置的排在最深前置的下一列；只掛在第一個同職業前置底下，其他前置照樣拉線；前置在別的職業時不拉線，自己當樹根。一排放不下就另起一排。
- 線上寫要練到幾級，前置滿的線亮、沒滿的暗；前置不夠的技能褪色但看得到，現在學得起的圈金線。
