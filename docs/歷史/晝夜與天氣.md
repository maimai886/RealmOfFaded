# 晝夜與天氣

2026-09-17 使用者提出並要求先記錄，還沒有實作：
「天氣 跟 晝夜 對怪物要有影響比較有趣 例如對啥屬性 在白天 還是晚上 有削落 或是增強 或是霧天 還是雨天晴天等等」

方向來自 Samsara Saga，它的日夜循環和天氣會實際影響移動和戰鬥，見 `docs/歷史/畫面質感檢查.md` 的美術方向決定。

## 為什麼值得做

我們已經有九種屬性和一張 9×9 相剋表，但**相剋表是靜態的**：水永遠剋火，玩家查一次就記住了，之後不會再想它。
晝夜和天氣把同一張表變成會動的東西——同一隻怪在不同時間要用不同打法，
而且**這是一個不用寫任何說明文字就能被玩家自己發現的機制**，正好符合「什麼都不教你」的設定。

## 已經確認的技術條件

調查結果在 `docs/歷史/畫面質感檢查.md` 和打光那一輪的報告裡，重點：

- 晝夜只要把 `map_environment.gd` 的 `MOODS` 從常數改成「時間 → 值」的插值，**不增加任何繪製次數**
- 時間同步不需要新的網路訊息，`src/net/server_clock.gd` 已經在同步伺服器時間
- 天氣可以用同一套插值框架加一組覆寫值，畫面成本一樣接近零；下雨的粒子和地面濕潤才是工作量
- 地窟要排除，它是室內，不跟地表的時鐘

## 設計方向，還沒定案

### 屬性隨時段強弱

最直覺、最好被發現的一組：

| 時段 | 增強 | 削弱 |
|---|---|---|
| 白天 | 光 | 暗 |
| 夜晚 | 暗 | 光 |
| 黎明與黃昏 | 時間、空間 | 無 |

黎明和黃昏給時間與空間，是因為那兩個屬性在設定上本來就跟「交界」有關，
而且這樣一天之中有兩個短暫的窗口會讓平常沒人用的屬性突然變成正解。

### 屬性隨天氣強弱

| 天氣 | 增強 | 削弱 |
|---|---|---|
| 晴 | 火、光 | 水 |
| 雨 | 水、風 | 火 |
| 霧 | 暗 | 光、風 |
| 雪或暴風 | 水、風 | 火 |

土刻意不受任何天氣影響，當作整張表的定錨——永遠有一個穩定的選擇。

### 不只是數字

只改傷害倍率會變成一張要背的表。更值得做的是**行為也跟著變**：

- 不死系在夜晚更活躍：偵測範圍變大、移動變快，白天則相反
- 霧天所有單位的偵測範圍縮短，包括怪物看不到你，所以霧天適合穿越危險區域
- 雨天地面濕滑，可以影響移動或翻滾距離
- 某些怪只在特定時段或天氣出現

最後一條要小心：限時出現的怪很容易變成「不在線上就錯過」，
那跟這個專案「想去哪就去哪、不限制你」的設定衝突。若要做，應該是**多一個機會而不是唯一的機會**。

## 對精煉與製作的影響：當成彩蛋

2026-09-17 使用者追加：「當作彩蛋 但不寫任何提示在遊戲中 就是天氣系統對精煉以及製作也要有影響」。

方向確定，但有兩個問題必須先解決，否則這個彩蛋會變成一個看不見的懲罰。

### 問題一：精煉會爆裝，隱藏的懲罰和隱藏的獎勵不對稱

精煉失敗會把裝備整件打爆，連材料和金幣一起賠。
如果天氣會**偷偷降低**成功率，玩家就會在完全不知情的狀況下賠掉東西——
他不會覺得「原來天氣有影響」，只會覺得「這遊戲在坑我」。

所以對精煉這種破壞性系統，**隱藏的效果只能往上不能往下**：
某些天氣或時段給一點加成，其餘時候是基準值，沒有任何天氣會讓成功率低於基準。
製作不同，製作失敗只賠一半材料、裝備不會爆，所以製作可以有上有下。

### 問題二：精煉的樣本數太少，藏起來等於不存在

一個玩家一生精煉的次數是幾十次等級，不是幾千次。
在這種樣本數下，**3% 的差異在統計上是隱形的**——沒有人發現得了，那這個彩蛋等於沒做。
製作的次數高得多，比較有機會被發現。

兩個解法，選一個或都做：

1. **效果要夠大才藏得住意義。** 例如雷雨天精煉成功率有明顯加成，
   大到玩家連續幾次之後會起疑。但這會讓「挑天氣精煉」變成最佳解，
   跟前面那條「不能變成挑時間上線的稅」衝突。
2. **給非文字的線索。** 這是比較好的解法，也符合「不寫說明」而不是「完全沒訊號」：
   鐵匠的爐火在某些天氣顏色不一樣、打鐵的音效不一樣、成功時的特效不一樣。
   玩家看得到有東西變了，但沒有人告訴他那代表什麼——那才是彩蛋，
   而不是一個藏起來沒人找得到的東西。

### 定案的做法

2026-09-17 使用者拍板，而且比我提的兩個方案都好：

**爐火會變色，但它本來就有機率會變，跟天氣無關也會發生。天氣只是提高它發生的機率，而且永遠不會降低。**

這個設計解掉了上面兩個問題，而且多了一層：

- **爐火變色是一個真實而且有意義的訊號**，它代表這一次有加成，不是代表天氣
- 因為它有基礎機率，所以**玩家在任何天氣都會偶爾看到**，不會以為是 bug，也不會完全遇不到
- 玩家先發現「藍色的火等於好事」，之後才會發現「下雨天藍火比較常出現」，**兩層發現**
- 天氣**只加不減**，所以永遠不存在「在錯的天氣被偷扣」這件事

### 爐火出現的時機：在精煉過程中，定案

2026-09-17 使用者拍板：**在精煉過程中出現，不是按下之前。**

所以它是純粹的回饋：按下去之後才知道這一次有沒有加成，玩家無法操作。
發現天氣的關聯之後，能做的是「挑下雨天去練一批」——那是一個要付出時間成本的真實決定。

不選另一個的理由：如果藍火在按下之前就出現，玩家會站在爐子前面等，
而等待是零成本的，所以它一定會變成最佳解，等於換一個形狀的稅。
一個讓玩家做無聊事的設計，比沒有這個設計更糟。

### 實作時要守住的

- **加成的判定在伺服器**，和精煉成功率的擲骰在同一個地方，客戶端只負責把爐火演出來
- 爐火的顏色是**判定的結果**，不是客戶端自己隨機決定的演出，否則畫面和實際結果會對不上
- 稽核要記下這一次有沒有加成，事後查得出來
- 基礎機率和各天氣的加成寫在 `data/refine.json` 或 `data/balance.json`，改曲線不用動程式
- 不寫任何說明文字，介面上不會出現「天氣」兩個字

## 三條必須守住的線

1. **伺服器說了算。** 時間和天氣由伺服器決定並廣播，客戶端只負責演出來。
   否則屬性倍率就變成客戶端可以操控的東西。

2. **不能變成「挑時間上線」的稅。** 如果夜晚打某個王明顯比較划算，玩家就會覺得白天在浪費時間。
   增強和削弱的幅度要小到「換個打法就好」，不要大到「該等到晚上再來」。

3. **不寫說明。** 照 CLAUDE.md 的規矩，介面不會解釋這個機制。
   所以效果必須**看得出來**——夜晚的不死系要有視覺上的變化、屬性倍率要反映在傷害數字上，
   讓玩家自己發現，而不是去讀一段文字。
