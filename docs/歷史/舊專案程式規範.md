# Realm of Faded 程式規範

> 2026-09-27 起這份寫的是舊專案 `../Sproutia` 的程式。新專案照 `Rust重構規劃.md` 重寫，寫到哪一塊就把那一段改成新的。

2026-09-18 依全面稽核寫成。這份是「這個專案怎麼寫程式」的唯一依據，和 `CLAUDE.md` 的程式規範一節一致，衝突時以 `CLAUDE.md` 為準並回頭修這份。
每一條都寫成可以拿去 grep 查的形式；第 8 節列現況違規的實例，修掉一條就從那裡劃掉一條。

稽核範圍：`src/` 185 個檔、`server/` 25 個檔、`tests/` 137 個檔，共約 11 萬行 GDScript。基準：`tests/run_tests.gd` 1316 個測試 0 失敗，`art_pipeline/tests/run.py` 135 個測試 0 失敗。

## 1. 語言與風格：對照 GDScript 官方風格指南

以 Godot 4 官方 GDScript style guide 為底，下面列本專案的採用與例外。

### 1.1 命名

| 對象 | 規則 | 例 |
|---|---|---|
| 檔名 | snake_case，和它主要的類別對應 | `battle_world.gd`、`json_file_database.gd` |
| 函式、變數、參數 | snake_case | `command_attack`、`entity_id` |
| 私有成員 | 前面加一個底線，只在檔內用 | `_entities`、`_apply_hit` |
| 常數 | 全大寫加底線 | `PICKUP_RANGE`、`DROP_OWNER_PROTECT_MS` |
| preload 出來的腳本常數 | PascalCase，和檔名對應 | `const BattleWorld := preload("res://src/core/battle_world.gd")` |
| 訊號 | snake_case，過去式或名詞，描述發生了什麼 | `hotbar_changed`、`setting_changed`、`tapped` |
| 內部類別 | PascalCase | `class ManualClock`、`class PendingRequest` |
| 沒用到的參數 | 前面加底線，不要刪，保持簽名一致 | `_agi`、`_at_position` |

現況：全專案沒有 camelCase 識別字、沒有小寫常數，這一節目前是乾淨的。

訊號名要能讀成「發生了什麼」：`hotbar_changed`、`shop_opened`、`cast_started`。名詞片語不算，例如 `log_message`、`chat_message`、`system_notice`、`refine_result`、`probe_mark`，這幾個在 `src/world/net_session.gd:205-254` 和 `src/world/battle_session.gd:29-44`，改名要連 hud 一起改，放重構計畫。

只在檔內用的函式一律加底線。現況 45 個公開函式只有自己檔在用，例如 `src/core/item_mods.gd:212 rarity_index`、`src/core/trade.gd:95 offer_size`、`server/services/party_service.gd:94 party_of`、`server/services/quest_service.gd:29 definitions`；安全相關的 `constant_time_equals`、`compute_journal_signature` 改名前先確認沒有外部腳本呼叫。

同一個概念只用一個名字，不要縮寫和全名混用。專案已經定案的名字：

- `character_id`，不是 `char_id`、`cid`
- `position`，區域變數才可以用 `point`；`pos` 只出現在 19 處，新程式不要再用
- `direction` 是完整的方向，`dir` 只用在協定欄位 `move.dir` 和它的直接相鄰程式
- `max_hp`、`max_sp`，不是 `hp_max`
- `gold` 是程式識別字，畫面上一律寫「金幣」，走 `UiText.gold_text`
- `item_id` 是程式與協定裡的道具引用；資料檔裡目前是 `item`，見 3.3 的待統一項
- 毫秒一律 `_ms` 後綴，秒一律 `_seconds` 後綴，公尺一律 `_m` 後綴

### 1.2 型別標註

- 函式一定寫回傳型別，沒有回傳就寫 `-> void`
- 參數一定寫型別。唯一例外：值可能是 `null` 或多種型別的 JSON 資料，這時不寫型別，並且在函式註解裡說它為什麼是 Variant
- 區域變數能推斷就用 `:=`；從字典拿出來的值一律先轉型再用：`int(d.get("x", 0))`、`String(d.get("id", ""))`、`float(...)`
- `var x = ...` 沒有型別只允許三種情況：拿到的是 JSON 解析結果、`dict.get()` 可能回 `null`、故意要接多種物件。其他一律補上
- 不要為了通過型別檢查用 `as` 硬轉；`as` 失敗回 `null` 會把錯誤往後推

現況統計：函式沒回傳型別 49 個（src 41、server 5、tests 3），區域變數 `var x = ` 沒型別 870 個，其中八成是刻意的 Variant。第 8.5 節列出可以補的。

### 1.3 常數與魔法數字

- 遊戲數值一律進 `data/balance.json`，程式用 `Formulas.tuning(section, key, fallback)` 讀；程式裡的常數只能是「結構上的」數字，例如陣列長度上限、協定版本、檔案路徑
- 出現兩次以上的同一個數字要有名字；同一個規格在兩個檔案各寫一份是違規，例如 `NPC_TALK_DISTANCE` 和 `SMITH_DISTANCE` 都是 3.0
- 百分比用整數 `percent`，千分比用整數 `permille`，兩者換算的基數 100 和 1000 允許裸寫，但同一行不要混用
- 浮點誤差門檻不要裸寫 `0.000001`，用一個具名常數，客戶端預測和伺服器要用同一個

### 1.4 訊號與事件

- 純邏輯層 `src/core/` 不用 signal，用回傳的事件陣列；`BattleWorld.step()` 回傳事件，表現層自己迭代
- 場景層與介面層用 signal，訊號只帶資料不帶節點
- 一個操作是一個指令，一個結果是一個事件，介面只訂閱事件不直接改狀態
- 連接訊號用 `signal_name.connect(callable)`，不用字串名

### 1.5 preload 與 class_name

- **不用 `class_name`**。原因：專案要能在同一個 Godot 裡同時開發版和穩定版並存、`--check-only` 看不到全域類別、匯出時 `server/` 目錄整個剔除，全域類別名會讓客戶端匯出去參照不存在的檔
- 引用其他腳本一律 `const Name := preload("res://path/file.gd")`，放在檔案最上面的常數區
- 函式裡面不要 `preload`。現況有一處例外在 `src/world/battle_session.gd:361` 的 `var MoveMath := preload(...)`，列在 8.5
- 執行期動態 `load()` 只允許載入資源與場景，不允許載入腳本。現況一處例外在 `src/ui/settings_window.gd:366`
- 型別標註可以直接用 preload 常數當型別：`func luk_of(character: CharacterData, registry: Registry) -> int`

### 1.6 檔案結構順序

照官方順序，從上到下：

1. `extends`
2. 檔案說明註解 `##`，第一句講這個檔是做什麼的，之後講為什麼這樣設計
3. `signal`
4. `enum`
5. `const`：先 preload 常數，再其他常數
6. `@export`
7. 公開 `var`
8. 私有 `var`
9. `@onready var`
10. 內部 `class`
11. `_init`、`_ready`、其他引擎生命週期
12. 公開方法
13. 私有方法，用 `# ---- 區段名 ----` 分段

規則：函式開始之後不可以再出現檔案層級的 `const`、`var`、`signal`。現況 12 個檔違規，列在 8.4。

signal 放在 const 前面。現況 `src/world/net_session.gd:204`、`src/ui/hud.gd:115`、`src/game_state.gd:201` 三個檔把 signal 放在 const 後面，調整只是搬動宣告，列在 8.4。

公開方法在前、私有方法在後是官方順序。本專案允許「一組公開入口緊接著它的私有輔助」的分組寫法，條件是用 `# ---- 區段名 ----` 標出每一組，`src/core/battle_world.gd` 是這樣寫的。沒有分段又公私交錯的算違規。

### 1.7 其他寫法

- 縮排用 tab，一行不超過 120 字，超過用反斜線換行並多縮一層
- 函式之間空兩行，區段註解前後空兩行
- 條件太長就先算成有名字的布林變數
- 巢狀不超過 4 層；超過就抽函式或提早 `return`
- 一個函式不超過 60 行；`match` 分派型的函式可以到 80 行，但每個分支不超過 10 行，長的分支抽成 `_on_xxx_event`。純分派表例外：每個分支只有一到三行、只是把參數轉給別的函式，例如 `server/world/player_commands.gd handle`，長度不限
- 不留 `print` 除錯，正式的紀錄走 `push_error`、`push_warning` 或各層自己的 `log_message`；`server/` 的 `_log` 和 `src/net/game_client.gd` 啟動訊息是允許的
- 不留 TODO、FIXME；要做的事寫進 `docs/進度.md`。現況零筆，維持

## 3. 伺服器權威與資料檔

### 3.1 只能在伺服器算的東西

位置、HP、SP、經驗、等級、屬性點、技能點、技能等級、冷卻、增益、道具、裝備、金錢、掉落、精煉與詞綴的擲骰、任務進度、隊伍與交易狀態、對話狀態、地圖切換。客戶端沒有任何指令可以直接設定這些值，`BattleWorld.allow_external_position` 在伺服器一律是 false。

客戶端可以做的三件事：

- 送意圖：走到哪、打誰、用什麼
- 預測自己的移動與揮擊，收到伺服器結果後對齊或回滾
- 用同一份 `data/*.json` 算「顯示用」的數字，例如冷卻遮罩、升級所需經驗、商店總價

第三件事的規則：**顯示用的重算只能影響畫面，不可以決定按鈕能不能按以外的任何事，而且伺服器一定重算一次**。現況合規，但 8.2 列出幾條「客戶端有第二份公式」的漂移風險。

### 3.2 伺服器端每一則指令的關卡

`server/net/session.gd:161-199` 的順序固定：大小與 JSON → 頻率桶 → 請求 id 遞增 → `Protocol.validate` 欄位 schema → 登入與在地圖狀態 → 分派。新增指令一定要：

1. 在 `src/net/protocol.gd` 加 schema，只列需要的欄位，多送的欄位會被丟掉
2. 在 `server/security/rate_limiter.gd` 的 `CATEGORY_LIMITS` 歸類，不可以只靠總量桶
3. 距離、冷卻、狀態的驗證寫在 `server/world/player_commands.gd` 或對應的 service，用 `server.now_ms()`，不用客戶端的時間
4. 在 `docs/伺服器架構.md` 的契約表加一列
5. 在 `tests/test_security_*.gd` 補一條惡意輸入測試

### 3.3 資料檔 `data/*.json` 欄位規範

- id 一律 `[a-z0-9_]`，`protocol.gd:557` 會擋不合的
- 顯示名稱一律 `name`，不用 `display_name`、`label`、`title`。現況一致
- 毫秒欄位一律 `_ms` 後綴，秒一律 `_seconds`，公尺一律 `_m`。現況兩個例外：`monsters.json` 的 `stats.attack_delay` 是秒沒後綴、`respawn_seconds` 合規
- 道具引用一律 `item`，數量一律 `count`。現況 `quests.json` 獎勵用 `item_id` + `amount`、`recipes.json` 成品用 `result` + `result_count`，列在 8.3 待統一，統一時要和讀它的程式一起改並過測試
- 頂層結構分兩派：裸 id 表和有信封的。新檔一律用信封 `{"source": ..., "notes": ..., "<複數名詞>": {id: {...}}}`，舊檔不動，`skill_data.gd:40` 的探測邏輯在兩派統一之前留著
- 說明欄位一律叫 `note` 或 `notes`，讀資料的程式一律跳過這兩個鍵
- 載入時要驗欄位。現況只有 `map_data.gd` 做到，其他檔的檢查在 `server/dev/data_editor.gd:180-270` 但只在後台編輯時跑，見重構計畫

### 3.4 匯出排除

`server/`、`server_data/`、`*.key`、`src/dev/` 以外的開發場景，在 `export_presets.cfg` 排除。任何生產程式 preload `server/` 底下的檔都會讓客戶端匯出壞掉，所以 2.1 的表是硬規則。

## 4. 註解規則

- 繁體中文，白話，不用括號補充；要補充就另起一句。現況 8 行含全形括號，列在 8.6
- 說為什麼不說做什麼。函式名已經講了做什麼；註解講取捨、來源、坑
- 檔案第一行 `extends`，第二行起用 `##` 寫這個檔負責什麼、不負責什麼、和誰分工
- 常數上方用 `##` 寫它的來源，例如「照 rAthena conf/battle/items.conf 的 item_first_get_time」
- 引用參考作品時附參數，例如「rAthena 預設 3000 毫秒」
- 使用者定案的規則要寫日期，例如「2026-09-17 使用者定案」
- 區段用 `# ---- 名稱 ----`，函式內的解釋用 `#`，文件型註解用 `##`
- 不寫作者、不寫修改紀錄，那是 git 的事

## 5. 測試規範

### 5.1 框架

- 測試檔 `tests/test_*.gd`，`extends "res://tests/test_case.gd"`；惡意客戶端測試 `extends "res://tests/security_case.gd"`
- 方法名 `test_` 開頭，`run_tests.gd` 用 `get_script_method_list` 找，拼錯就不會跑，所以檔案最後看一次總數有沒有變
- 斷言只有三個：`assert_eq(actual, expected, message)`、`assert_true(condition, message)`、`assert_near(actual, expected, tolerance, message)`。message 是中文，寫「應該怎樣」，一定要給，現況 184 個斷言沒有 message，失敗時只印「預期 X 實際 Y」不知道是哪一條
- 比對相等用 `assert_eq`，不用 `assert_true(a == b)`，後者失敗看不到實際值；布林用 `assert_true`，不用 `assert_eq(x, true)`。現況 433 處 `assert_eq(..., true)`，例外是 `dict.get()` 回來可能是 null 的值
- 不用引擎原生 `assert()`，release 建置會整段拿掉。現況三處：`tests/security_case.gd:123`、`tests/test_server_skills.gd:65`、`tests/test_server_session.gd:67`
- 測試檔內的輔助函式加底線；只有 `security_case.gd`、`sprite_fixture.gd`、`monster_art_fixture.gd` 這種共用基底的公開方法不加
- 輔助函式不要用 `_test_` 開頭，會讓人以為是測試；現況 `tests/test_server_session.gd:91`、`tests/test_server_skills.gd:77` 的 `_test_map` 應改 `_make_map`
- `tests/test_server_session.gd:28`、`tests/test_server_skills.gd` 各抄了一份 `security_case.gd` 的 `Client` 和 `ManualClock`，新測試一律繼承 `security_case.gd`，不再抄
- 每個測試方法一個新的實例，不共享狀態；需要共用的建構寫成 `_make_xxx()` 私有函式
- 測試裡出現引擎錯誤也算失敗，所以不要用會 push_error 的路徑當正常流程
- 時間用 `ManualClock` 或直接傳毫秒整數，不用 `await`、不用 `Time.get_ticks_msec()`
- 不開 socket，`security_case.gd` 直接把文字餵給 Session

### 5.2 一個修 bug 要附一條測試

- 修 bug 的 commit 一定包含一條會在修之前失敗、修之後通過的測試
- 玩家會遇到的缺陷放 `tests/test_qa_regressions.gd`，測試上方的 `##` 寫原本玩家會遇到什麼
- 安全相關放對應的 `tests/test_security_*.gd`
- 數值相關動到 `data/balance.json` 時 `tests/test_balance.gd` 會紅，更新預期值，不放寬帶子
- 測試方法名用英文 snake_case 描述情境，例如 `test_pickup_refused_when_gold_limit`；中文寫在 message 和註解
