# 精靈圖顯示校正

2026-09-15 起。場景的色調映射會改掉精靈圖的顏色，例如 AgX 加曝光 1.1 會把 `#8a5a30` 的棕髮顯示成偏橘的 `#c78163`。
螢幕上要看到的就是圖裡畫的顏色和 `data/appearances.json` 寫的色階，所以精靈圖材質走 unshaded，
並在著色器裡先把色調映射反算掉，不管環境之後改用哪一種色調映射都成立。做法在 `src/world/actors/display_grading.gd`。

2026-09-23 換了做法。以前假設輸出流程是「矩陣 A → 每個通道各自一條曲線 → 矩陣 B」，用灰階量曲線再反算，
灰色是準的，飽和色和暗色不準：實測純紅在畫面上變成 (255,123,100)、深色 30 變 55，角色整個灰掉，使用者說失真。
現在不猜公式，直接量整個三維的顏色空間。

2026-09-25 起校正的目標不再是原圖的顏色。原圖照原樣全彩全對比畫出來，放在有空氣感的場景裡很搶戲，
所以著色器先把飽和度收到 0.82、最暗的地方往霧色提一點，這才是「最後想看到的顏色」，再照這一份校正；
引擎的霧也不再對角色關掉，和地面同一層。參數是 `sprite_recolor.gdshaderinc` 的 `blend_saturation`、`blend_lift`、`blend_haze`。

## Godot 4.7 的輸出流程

從 Godot 原始碼的 `tonemap.glsl` 讀出來的順序，Forward+ 和 Mobile 都一樣：

1. 顏色 × 曝光
2. 色調映射：`LINEAR` 什麼都不做；`REINHARD`、`FILMIC` 是每個通道各自一條曲線；
   `ACES` 和 `AGX` 是矩陣 → 曲線 → 矩陣，AgX 的曲線是 4.5 起的 allenwp 曲線，參數在 C++ 端算
3. 有開色彩調整時：× 亮度 → 線性轉 sRGB → 對比 `mix(0.5, c, contrast)` → 飽和度 `mix(平均值, c, saturation)`；
   沒開時只做線性轉 sRGB
4. 色彩校正貼圖，這裡不支援，有設定會警告

AgX 的兩個矩陣會把通道混在一起，量灰階只量得到曲線，混色的部分在灰階上看不到。與其追每個版本的參數，不如把顏色真的丟進去算。

## 怎麼量

1. 把場景的 Environment 複製一份，關掉泛光、霧、SSAO 這些會混到鄰近像素的東西，只留色調映射和色彩調整
2. 目標顏色是 sRGB 每個通道 21 階的立方體，9261 個顏色。第一次的候選是目標直接轉成線性色
3. 候選排成一張 441×21 的四通道浮點圖，x 是 `r + 21 × b`、y 是 `g`，貼在一個 441×21 的 SubViewport 裡的紙片上，
   unshaded 材質直接輸出貼圖的值，相機掛上那份 Environment；等兩個畫面後讀回像素
4. 讀回來的顏色和目標比，差多少就把候選往回推，在線性色裡算；第二次起拿上一次的候選和量到的值算斜率當步長，
   AgX 肩部那種壓得很扁的地方才收斂得快。讀回來只有 8 位元，變化小於 2.5 階不拿來算斜率，不然暗部會算出亂七八糟的斜率
5. 來回 8 次就收斂，候選存成反查表：和探針同一種排法的 441×21 浮點圖，著色器自己做三線性內插

一定要四通道的浮點格式：三通道的浮點貼圖很多顯示卡不支援，Godot 會退成 8 位元，超過 1 的值全被夾掉。
反查表也不用 3D 貼圖，實測 `ImageTexture3D` 的浮點格式到了顯示卡一樣被夾成 0 到 1。

SubViewport 不一定會做色彩調整：Godot 4.7 的 Mobile 渲染器對 SubViewport 不做亮度、對比、飽和度，主畫面卻做。
所以有色彩調整時先量一張有調整和一張沒調整的，兩張一樣就代表 SubViewport 沒做，解的目標先扣掉調整，著色器再扣一次真的。

每種環境設定只量一次，key 是色調映射種類、曝光、白點、亮度、對比、飽和度。換地圖時環境重建，角色每 0.5 秒確認一次 key 有沒有變。
一次校正在 1280×720 約半秒，這段時間角色先用沒抵銷的顏色。

## 線性值的上限和泛光

AgX 的肩部很長，要到螢幕的純白得餵六倍的線性值。但泛光會把那麼亮的像素當成光源，整個角色暈成一片、旁邊的顏色全被染白，
實測黑色塊被染到 98。所以候選夾在 2 倍：純白在白天畫面上是 231 左右，和太陽下的白牆一樣亮；
白天和黃金時刻的泛光門檻同時提到 2.05，角色的亮部不會再被泛光暈開。夜晚門檻 0.8 沒動，角色在夜裡本來就暗。

2026-09-23 實測，1280×720、Forward+、白天 AgX 曝光 1.08 對比 1.04 飽和 1.1，泛光門檻 2.05：

| 目標 | 畫面上 |
|---|---|
| 皮膚 (251,237,217) | (232,231,222)，被上限夾到 |
| 布料 (129,95,77) | (129,95,76) |
| 灰 (128,128,128) | (128,128,127) |
| 深 (30,30,30) | (30,30,30) |
| 藍 (40,60,200) | (45,65,204) |
| 純紅 (255,0,0) | (252,82,43)，AgX 的色域到不了 |
| 純白 | (231,231,231)，被上限夾到 |

## 著色器裡的反算

目標是「螢幕上要看到的 sRGB 顏色」`t`，著色器要輸出的線性色 `c`：

```
t → 色彩調整反算（探針量得到調整時是 1，什麼都不做）→ 查 3D 反查表，兩片之間再混一次 → c
```

沒有環境的 viewport，例如選角預覽的 SubViewport，key 是空字串，材質不抵銷。

## 沒抵銷的部分

- 超過上限的亮色：純白和很亮的膚色會停在 231 到 238
- AgX 色域到不了的純色：純紅、純綠的另外兩個通道會浮起來，畫裡沒有這麼純的顏色
- 泛光的 `glow_bloom` 會把整張畫面模糊後加回去，夜晚有 0.2，角色會被周圍的顏色染到一點
- 色彩校正貼圖

## 相容渲染器

2026-09-27 起。網頁版和手機走相容渲染器，Godot 4.7.2 實測和 Forward+ 差兩件事：

1. 整條管線在 sRGB 空間：`source_color` 的貼圖和參數取出來不轉線性，ALBEDO 也不編碼就上畫面。
   線性色調映射下 ALBEDO 寫 0.5 畫面是 128，Forward+ 是 188。著色器用 `as_linear` 把取進來的顏色先轉線性，
   沒有顯示校正時 `to_output` 再轉回去；兩個函式在 Forward+ 什麼都不做。
   以前沒轉，貼圖被當成線性色再編碼一次，粉色皮膚 (240,200,190) 在畫面上變成 (250,249,246)
2. 開了色彩調整又沒開泛光時先畫進 8 位元緩衝，超過 1 的線性值在色調映射前就被夾掉，最亮只到 206；
   開泛光才畫進浮點緩衝。所以主畫面有泛光時探針也開泛光，強度和各層歸零只借緩衝，key 多一個 `hdr`

相容渲染器的暗部壓得很死，輸入 0.05 出來 0、0.2 出來 41，照線性色解八次推不到目標，
所以相容渲染器的候選從目標本身開始、直接用 sRGB 的差推。

實測 1280×720 相容渲染器、AgX 曝光 1.08 對比 1.04 飽和 1.1、有泛光，精靈圖著色器關掉融進場景那一步：

| 目標 | 畫面上 |
|---|---|
| 皮膚 (240,200,190) | (240,200,190) |
| 淺膚 (251,237,217) | (250,237,218) |
| 布料 (129,95,77) | (129,94,78) |
| 灰 (128,128,128) | (128,128,128) |
| 深 (60,45,40) | (60,46,41) |

沒開泛光的畫質設定下，相容渲染器的亮色最多 206，著色器救不回來。

## 怎麼檢查

最直接的：做一張候選身體，畫格裡放幾個平塗色塊，`--body=` 進遊戲截圖，讀每個色塊的中位數和目標比。
2026-09-23 就是這樣量的，腳本在對話紀錄裡，要再量就照上面那張表重做。

`res://scenes/dev/sprite_viewer.tscn -- --swatch` 也還在：場景中央放 `color_ramps.gd` 拼出來的色階色塊，
`--no-glow` 關掉泛光量校正本身，`--no-grading` 看改前的樣子。
