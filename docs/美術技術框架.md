# 美術技術框架

所有美術產出要遵守的硬數字集中在這一份。要改任何數字，先改這裡，再改出處。畫風在 `docs/美術風格指南.md`。

## 1. 引擎與渲染

| 項目 | 值 |
|---|---|
| 引擎 | Godot 4.7，世界表現是 Rust 擴充 `rof-gdext`，只有介面用 GDScript |
| 渲染器 | 桌機 Forward+、手機 mobile；沒有 Vulkan 的電腦和網頁走相容渲染器 |
| VRAM 壓縮 | `import_s3tc_bptc` 和 `import_etc2_astc` 都開，桌機 BC7、手機 ASTC 4×4，每像素都是 1 位元組 |
| 抗鋸齒 | FXAA 或 MSAA，全專案不用 TAA |

Mobile 不支援全域光照、環境遮蔽、體積霧、螢幕空間反射，兩條路徑每次改完都要各看一次。
自己寫 DEPTH 或讀深度貼圖的著色器要用 `CURRENT_RENDERER` 分開：Forward+ 和 Mobile 的裁切空間 z 除以 w 是 0 到 1，相容渲染器是 −1 到 1。

## 2. 鏡頭

| 項目 | 值 | 出處 |
|---|---|---|
| 投影 | 透視，垂直 FOV 15 度 | `rust/crates/gdext/src/camera.rs` |
| 俯角 | 鎖死 −45 度，玩家改不了 | 同上 |
| 距離 | 預設 52 公尺也是上限，可拉到 24 | `data/camera.json` |
| 基準距離 | 42.73 公尺，角色貼圖在 1080p 一比一 | |
| 近遠裁切 | 1 到 300 公尺 | `camera.rs` |
| 方位角 | 右鍵繞 Y 軸自由轉 | |

俯角和距離是整套美術的基準，改了要重算這份。俯角不影響每公尺像素，那是距離和 FOV 決定的。
產圖端的角度比遊戲淺：角色骨架用 30 度加 25 度抬頭投影，45 度算的話 2.8 頭身的臉會在頭的下半部看不到，RO 的角色圖也是比地面淺；
怪物方向圖是使用者畫的，要看得到頭頂就得從俯角畫。

## 3. 畫面尺寸

| 情境 | 尺寸 |
|---|---|
| 桌機最小視窗，驗收用這個 | 1440×810 |
| 專案設定的視窗 | 1280×720 |
| 手機橫式參考 | 844×390 |
| 介面縮放 | 0.8 到 1.4 |

## 4. 世界尺度

- 單位是公尺；對移動來說地面完全是平的，玩家站在 y = 0
- 高過地面 0.25 公尺的擺設擋路，擋路形狀一律方形
- 玩家身高 1.875 公尺，180 像素除以 96
- 怪物身高只由 `data/monsters.json` 的 `art.height` 決定，下限玩家的 0.44 倍約 0.62 公尺；`view_m` 至少是 `height` 的 1.25 倍，要量不要填

## 5. 像素密度

螢幕密度是 `畫面高度 ÷ (2 × 距離 × tan 7.5 度)`：1080p 在 42.73 公尺是 96、在 52 公尺是 79、在 24 公尺是 171；1440×810 在 42.73 公尺是 72；手機 390 高是 35。

| 對象 | 密度 |
|---|---|
| 玩家角色、NPC 立牌 | 96 像素一公尺，180 像素高，畫格 176×232，錨點 (88, 208) |
| 怪物 | `frame_px = 進位到 64 的倍數(view_m × 112)`，下限 128、上限 320 |
| 引擎退路 | 64，只在 meta 沒寫時用 |

96 是照基準距離訂的，貼圖在 1080p 一比一、2160p 剛好兩倍；怪物的 112 是照最近 24 公尺訂的。
出貨的南門四隻實際密度是萊姆和水晶兔 137、小樹苗 116、木樁王 76，被畫格上下限夾到。`art_pipeline/config.py` 的 80 是舊 3D 算圖的，沒人用。

## 6. 圖集格式

完整契約在 `docs/精靈圖規格.md`，這裡只列硬數字。

| 項目 | 值 |
|---|---|
| 方向 | 算 `s`、`sw`、`w`、`nw`、`n` 五個，`e`、`ne`、`se` 由引擎水平翻轉；引擎也吃八方向都算的圖集 |
| 背景 | 全透明 |
| 排版 | 8 欄，`layout: "packed"` |
| meta 必填 | `frame_size`、`columns`、`pixels_per_meter`、`anchor`、`directions`、`actions`、`filter` |
| 錨點 | 兩腳腳底中點，上面留空間給帽子和舉起的武器 |
| 換色遮罩 | 可選，R 頭髮、G 皮膚、B 主要布料；沒有時整張算主要布料；和彩圖一樣大或長寬同時縮成整數分之一，最多八分之一 |
| 怪物動作 | 待機、走路、攻擊、受擊、死亡，一般 135 格，大隻會超過上限時用 115 格 |

## 7. 匯入設定

由每份 `meta.json` 的 `filter` 決定，產圖端 `art_pipeline/common/sheet_output.py` 寫 `.import`。

| 檔案 | 壓縮 | mipmap | 其他 |
|---|---|---|---|
| 像素角色 `sheet.png`，`filter: "nearest"` | 無損 | 開 | `fix_alpha_border` 開；取樣用銳利雙線性 |
| 像素角色 `mask.png` | 無損 | 關 | 最近點 |
| 怪物 `sheet.png` | VRAM 壓縮，`high_quality` 一定開 | 開 | 平滑加 mipmap |
| 怪物 `mask.png` | 無損 | 開 | |
| 介面記號、圖示 | 無損 | 關 | 標題列記號存 64 縮下去，例外開 mipmap |
| 特效 `assets/vfx/impact_flash.png`，通道是資料 | VRAM 壓縮高品質 | 開 | `fix_alpha_border`、`premult_alpha` 都關 |

`high_quality` 關掉會退回 BC3 和 ETC2，色階誤差變兩三倍。

## 8. 記憶體與效能預算

| 項目 | 上限 |
|---|---|
| 一張地圖顯示記憶體 | 400 MB，含配置器保留 64 MB |
| 一張地圖全部貼圖 | 200 MB，其中怪物精靈圖 130 MB、最多八種怪 |
| 一份圖集的像素數 | 12,582,912，超過一份整張地圖多付 64 MB |
| 繪製次數 | 250 |
| 三角形 | 20 萬 |
| 幀時間 | 16.6 毫秒對 60 fps；低品質鎖 30 fps |
| 地圖材質 | 2048² 等效四張以內 |
| 單張對話立繪 | 50 到 66 萬像素 |

細節和量法在 `docs/效能與記憶體.md`。

## 9. 出貨

三個輸出設定都排除 `assets/generated/sprites/placeholder/*`，但引擎找不到正式圖時會退到那裡。
開發機上看起來好好的，出貨包裡那一隻就是空的，所以任何要出貨的東西都不能只有佔位圖。

## 10. 色彩與打光

| 項目 | 值 |
|---|---|
| 場景色調映射 | AgX，曝光 1.08，見 `scenes/maps/meadow.tscn` |
| 主光 | `#ffeecb` 暖白左上，冷補光右下 |
| 環境光 | 取天空色偏藍，任何地圖不低於 0.8，角色永遠看得到 |
| 陰影 | 偏紫，不用純黑 |
| 霧 | 只當景深提示，起霧點不小於 62 公尺，地窟例外 |
| 精靈圖 | 材質 unshaded，著色器反算環境的輸出，見 `docs/精靈圖顯示校正.md` |
| 地面貼花圖層 | 第 11 層只給地面，技能地裂這種 Decal 的 `cull_mask` 只開它，不然會印到角色和特效上；第 2 層是名字和血條 |

## 11. 還沒解決的

- 怪物要不要跟著像素化。現在怪物柔和、角色像素，同一畫面兩種質地
- 專案檔的視窗 1280×720 和實際最小視窗 1440×810 不一致，檢查表和密度換算有一半還用 1280×720
- 鏡頭拉到 24 公尺時角色頭頂露多少還沒實拍量過
- `art_pipeline/config.py` 的 `OUTLINE_COLOR` 幾乎是純黑，和帶色描邊的規則牴觸，只剩舊的 3D 算圖程式在用
- 匯入設定只有圖集那一塊有測試守，介面和其他貼圖沒有
