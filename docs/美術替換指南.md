# 美術替換指南

角色和怪物的美術之後還會再改幾輪，所以美術是一層可以整包換掉的東西，不是寫死在程式裡的。
這份文件寫清楚「要交出什麼東西，遊戲就會用它」。照這份做，不用碰一行程式。

- 畫風長什麼樣子看 `docs/美術風格指南.md`
- 角色的造型標準看 `docs/角色系統規格.md`
- 圖集的格式契約看 `docs/精靈圖規格.md`
- 怎麼產圖看 `docs/美術產線操作手冊.md`

## 1. 所有角色都是紙片圖集

玩家、NPC、怪物全部是 `src/world/actors/sprite_actor.gd` 的紙片角色，吃預先算好的多方向圖集。
2026-09-24 NPC 改成 2D 之後，使用者要求把 3D 角色整條拿掉，模型、腳本、資料欄位都清了，理由在 `docs/決策紀錄.md`。

| 誰 | 圖集在哪裡 | 看 look 的哪個欄位 |
|---|---|---|
| 玩家角色 | 所有職業、男女共用 `characters/body/male_novice` 這份素體底板；裝備疊 `characters/layers/<名稱>` | `gender` 加 `job_id` |
| NPC | `npcs/<npc_id>`，頭畫在身體那層 | `npc_id` |
| 怪物 | `monsters/<sheet>`，沒有再找 `monsters/<fallback_sheet>` | `data/monsters.json` 的 `art` 區塊 |

挑哪一份圖集由 `src/world/actors/actor_factory.gd` 的 `sprite_dir` 決定，程式不認任何一個 id。
找不到自己的圖集時 `sheet_or_placeholder` 改用玩家的共用底板頂著，同一份外觀只報一次錯，
所以資料還沒補完也不會變成空的角色。

玩家角色 2026-09-24 起所有職業、男女都用同一份素體底板，`sprite_sheet.character_body_dir` 不看職業，
一律找 `<性別>_novice`，女生沒有自己的就用 `male_novice`。職業外觀之後做成服裝圖層。

## 2. 標準骨架

紙偶的骨架投影 `art_pipeline/characters_v5/puppet_rig.py` 和 `cbuild.py` 都用這一副骨架，
定義在 `art_pipeline/characters_v3/humanoid.py`，比例參數在 `rigspec.py`。
骨頭名稱照 Mixamo 也就是 Unity Humanoid 那一套，不加 `mixamorig` 前綴，
市面上的動作包幾乎都用這組名字，之後買動作或用 Mixamo 產動作可以直接套。

共 62 根：

```
Root
  Hips
    Spine → Spine1 → Spine2
      Neck → Head → head              head 是頭飾掛點
      LeftShoulder  → LeftArm  → LeftForeArm  → LeftForeArmTwist  → LeftHand
      RightShoulder → RightArm → RightForeArm → RightForeArmTwist → RightHand
        LeftHandThumb1..3   LeftHandIndex1..3   LeftHandMiddle1..3   LeftHandRing1..3
        RightHandThumb1..3  RightHandIndex1..3  RightHandMiddle1..3  RightHandRing1..3
        hand_l / hand_r                武器掛點
      back / body                      披風和身體外觀掛點
    LeftUpLeg  → LeftLeg  → LeftFoot  → LeftToeBase  → LeftToeEnd   加 LeftUpLegTwist
    RightUpLeg → RightLeg → RightFoot → RightToeBase → RightToeEnd  加 RightUpLegTwist
  LeftHandIK / RightHandIK / LeftFootIK / RightFootIK    不變形，給需要 IK 的動作包用
```

`Root` 和 `Hips` 是分開的兩根，`Root` 在地板上。翻滾的翻轉打在 `Root`，
所以身體是繞著自己翻而不是原地轉圈。

動作沿用 KayKit 的 76 個動作，來源是 `assets/vendor/kaykit/characters/Knight.glb`，
`characters_v3/rig.py` 從它拿骨架和動作，`rig_humanoid.py` 改骨頭名字的時候把每個動作的軌道路徑一起改掉。
旋轉軌是無單位的，骨頭方向和 roll 不變就會擺出同一個姿勢，所以動作完全不用重做。
KayKit 其他角色模型 2026-09-24 清掉了，只有 `Knight.glb` 和它的貼圖一定要留著。

## 3. 資料要加什麼

### 加一個髮型或眼型

`data/appearances.json` 的 `options.hair_style.<gender>` 或 `options.eye_style` 加一筆 `{"name": "盤髮"}`。
捏臉介面、伺服器驗證的數量都照這份資料的筆數，索引就是頭圖集資料夾
`characters/head/<gender>_h<髮型>_e<眼型>` 的編號，找不到那一組時退回 `h0_e0`。
現在的素體底板在 meta 寫了 `head_layer: false`，頭畫在身體那層，所以換髮型眼型只換色、不換圖，
要分開換頭得先把頭從底板拆出來。

### 加一件裝備外觀

`data/items.json` 那件裝備的 `model_attachment` 就是圖層名稱，穿上時引擎找
`characters/layers/<名稱>_<性別>/`，沒有再找 `characters/layers/<名稱>/`。
圖層和身體同畫格、同錨點、同動作，每一格的 meta `order` 說它在身體前面還是後面。
產法有兩條，都在 `docs/美術產線操作手冊.md` 第 3 節：`puppet_layer.py` 吃每個方位各畫一張的圖，
`cbuild.py --layer` 吃 `assets/generated/models/characters/` 裡的武器、鎧甲、披風、頭盔網格。

**沒有圖層的裝備照樣能穿，只是不顯示外觀，只算數值。**

## 4. 怪物和 NPC 的圖集

格式契約在 `docs/精靈圖規格.md`，這裡只寫操作。

```
assets/generated/sprites/
  monsters/<sheet>/   sheet.png  meta.json  可選 mask.png
  npcs/<npc_id>/      sheet.png  meta.json  可選 mask.png
  placeholder/        同樣的結構，佔位圖放這裡
```

`mask.png` 是換色遮罩，只有分兩區以上的角色才放。整隻只有一種材質的怪不要放，
引擎看到資料夾裡沒有那個檔案就當成整張都是主要區域，換色照樣有效，而且省下和彩圖一樣多的記憶體。
放的話可以縮成彩圖的整數分之一，規則見 `docs/精靈圖規格.md` 的「換色遮罩」。

引擎找圖的順序：先 `assets/generated/sprites`，找不到再找底下的 `placeholder`。
怪物的 `sheet` 和 `fallback_sheet` 兩個名字都來自 `data/monsters.json` 的 `art` 區塊。

`meta.json` 必填 `frame_size`、`columns`、`pixels_per_meter`、`anchor`、`directions`、`actions`，
另外三個可選欄位可以蓋掉引擎的預設：`depth_nudge`、`shadow_radius`、`ramp_span`。
引擎不假設任何產圖端的數字，格子多大、每公尺幾個像素、腳底在哪裡全部從 meta 讀，
所以新美術的比例和舊的完全不同也沒關係。

格式錯了載入時會印出錯誤訊息，每一條都直接說哪個欄位怎麼了：

- `actions.attack.frames 是 10，比 columns 的 8 還多，圖集寬度放不下`
- `圖片是 1536x7680，但 meta 說應該是 1536x5760`
- `anchor (96, 250) 落在格子 192x192 之外`
- `遮罩是 768x1920，圖集是 1536x7680。遮罩要嘛和圖集一樣大，要嘛長寬同時縮成整數分之一`
- `meta.json 少了 idle 動作，角色站著不動時沒有東西可以播`

檢查的程式在 `src/world/sprite_sheet.gd` 的 `check_meta` 和 `check_grid`。

## 4.5 NPC 對話立繪

2026-09-16 加，2026-09-17 九張圖全部到位。對話框右邊那張大圖，玩家和 NPC 講話時站在框後面、
下緣被對話框切掉。**這是純資料，換圖不用改任何程式。**

```
assets/ui/portraits/<立繪編號>.png
```

`data/npcs.json` 每個 NPC 的 `portrait` 欄位填立繪編號，解析在 `src/ui/ui_portraits.gd`，
做法和 `ui_icons.gd` 找道具圖示一樣：檔案在就用，不在就回傳 null。
**沒有立繪的 NPC 一樣能講話**，對話框會自己占滿整排寬度。

規格：

| 項目 | 值 | 為什麼 |
|---|---|---|
| 原圖 | 1024×1536 直式，產完裁到人物本身再縮到高 960 | 對話框在最小視窗 1440×810 上把人畫到約 560 像素高，視窗放到最大約 1120 |
| 背景 | 全透明，裁到人物本身 | 對話框自己算位置，圖上有留白人物會看起來歪掉 |
| 構圖 | 站姿全身，頭到腳都在畫面裡 | 三頭身的角色砍掉腳會很怪，下緣讓對話框自己切 |
| 格式 | PNG，一般介面貼圖匯入設定 | 一次只會載一張，不必為它開 VRAM 壓縮 |
| 一張圖的像素 | 50 到 66 萬，遠低於 `docs/效能與記憶體.md` 的 1258 萬上限 | 不會讓任何一張地圖多付一階配置器保留 |

放進去之後跑 `godot --headless --path . --import`，再照第 6 節截圖看一次。

### 產這一組圖的描述

風格對的是 `docs/美術風格指南.md`：三頭身、圓潤、大眼睛兩點高光、柔和漸層、偏暖的中低飽和。
**整組的一致性比單張好看重要**：同一個線寬、同一種上色、同一組色溫、同一種眼睛、同一個取景。
做法是先把第一張調到滿意，把描述定下來，剩下八張只換角色本身那一段，其他一個字都不要動。

固定不動的那幾段，照這個順序寫：

> 原創角色立繪，全透明背景去背，沒有外框。
> 角色：<只有這一段每個人不一樣>
> 比例：三頭身的 Q 版，頭大約佔全身的三分之一，身體短而圓，手短，手是圓潤的連指形狀，圓頭鞋。
> 全部由大圓形組成、沒有銳角，剪影一眼就認得出來。
> 臉：畫上去的不是做出來的。很大的眼睛有眼白、虹膜從上暗到下亮有漸層、深色瞳孔、兩點白色高光。
> 細眼線、額頭上看得到細短眉毛、鼻子只有一點陰影、小嘴、淡淡的腮紅。
> 取景：畫面裡只有一個角色，站姿全身從頭頂到腳，身體轉四分之三面向觀眾，置中，
> 四邊都留一點空白讓人物不碰到畫面邊緣。畫面裡沒有別的東西：沒有背景、沒有邊框、沒有文字、沒有地面陰影。
> 畫風：柔和漸層的賽璐璐上色，亮到暗是平滑過渡，暗部帶一點冷色反光；乾淨的細線稿，
> 線是暖深棕不是黑；材質乾淨沒有雜訊也沒有布紋。整體偏暖的中低飽和粉彩配色，
> 加一兩個小面積的高飽和重點色，亮部收在暖奶油色，沒有中性灰、沒有純黑。
> 手繪 2D 遊戲立繪，不是 3D 算圖，不是照片。

每個角色只換「角色」那一段：長相、髮型髮色、衣服顏色、手上的東西、表情和姿勢。

## 5. 匯入設定

圖集不走一般貼圖的匯入預設：彩圖用高品質 VRAM 壓縮、遮罩無損，兩種都要 mipmap，
完整的表在 `docs/精靈圖規格.md` 的「匯入設定」。產圖管線會自己寫好，手工放圖的話跑這兩個指令：

```
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://src/dev/fix_sprite_imports.gd
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

加了新檔案之後跑一次 `--import` 就好。

## 6. 五分鐘內在遊戲裡驗證

```
cd ~/Desktop/project/RealmOfFaded
# 捏角畫面：換性別、髮型、髮色、膚色，看角色有沒有跟著變
/Applications/Godot.app/Contents/MacOS/Godot --path . --resolution 1280x720 \
  --write-movie /tmp/check/f.png --fixed-fps 10 --quit-after 70 -- --dev-page=create
# 實際遊玩畫面：看角色站在地上、大小合理、臉在鏡頭預設距離下看得清楚
/Applications/Godot.app/Contents/MacOS/Godot --path . --resolution 1280x720 \
  --write-movie /tmp/check2/f.png --fixed-fps 10 --quit-after 70 -- --dev-page=game
# 怪物和 NPC 的圖集：八個方向、攻擊、受擊、死亡
/Applications/Godot.app/Contents/MacOS/Godot --path . --resolution 1280x720 \
  --write-movie /tmp/check3/f.png --fixed-fps 10 --quit-after 70 res://scenes/dev/sprite_viewer.tscn
```

看最後幾張圖，逐條確認：

1. 腳底踩在地上，沒有陷進去也沒有浮起來
2. 武器圖層掛在手上，每個方向在身體前後的順序對
3. 換髮色、膚色、服裝色都有作用，而且眼睛和嘴巴的顏色不會跟著變
4. 角色大小和旁邊的怪物、建築比起來合理

最後跑測試，資料格式不對會直接失敗並印出哪個欄位要修：

```
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tests/run_tests.gd
```

相關的測試：`tests/test_actor_factory.gd` 管找圖集和缺圖時的底板，`tests/test_sprite_actor.gd`
管播動作、掛頭、裝備圖層、翻滾，`tests/test_sprite_sheet.gd` 管圖集格式，
另外 `tests/test_npc_art.gd`、`tests/test_monster_art.gd` 守 NPC 和怪物的資料。
