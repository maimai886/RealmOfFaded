# 美術產線操作手冊

2026-09-23 建立，2026-09-24 清掉已刪除的管線。給使用者自己在這台電腦上生產角色、怪物、裝備、裝飾用的，每一步都是一行指令。
為什麼是這套做法在 `docs/決策紀錄.md` 2026-09-23 那條；接手的 AI 看 `docs/美術產線接手紀錄.md`。

一句話：**長相和筆觸是你畫的，方向和動作是零件照骨架動。** 你畫五個方向的視圖，
本機把它切成頭、軀幹、四肢零件，照標準骨架每一格的姿勢疊回去，算成八個方向、八個動作的圖集。
每一格都是同一張圖的變形，所以一定一致。全部本機、不花錢。

2026-09-24 使用者叫美術先停，下一件是 NPC 改成 2D 圖集、對話立繪重畫成日系動畫風，進度看接手紀錄 0.5。

## 0. 前置

- Blender 5.2 在 `D:\Program Files\Blender Foundation\Blender 5.2\blender.exe`，下面寫 `blender` 的地方都是這個路徑
- 指令都在專案根目錄跑
- 角色骨架投影約 2 分鐘、切零件組圖集幾十秒；一隻怪幾秒

## 1. 角色：紙偶，你畫的視圖切零件照骨架動

所有職業都用同一份素體底板，男女也共用 `male_novice`，只差髮型和身上的裝備，職業外觀之後做成服裝圖層。
你畫的五張視圖去背後切成頭、軀幹、上臂、前臂、大腿、小腿、腳，每一格照標準骨架的動作把零件平移旋轉縮放疊回去；
站姿第 0 格就是你的原圖，臉和筆觸不經過任何生成。

輸入：`art_source/characters_v5/<身體>/views/` 裡 s、sw、w、nw、n 五張，白底，站直、手臂垂下，正面朝鏡頭那張是 s。

```
# 1. 骨架投影：從幾何人偶的標準骨架算出每一格每個零件在畫面上的線段，Blender 跑約 2 分鐘
blender -b --factory-startup --python-exit-code 1 -P art_pipeline/characters_v5/puppet_rig.py -- art_pipeline/_build/puppet_rig --job novice --gender male

# 2. 切零件組圖集，幾十秒。--candidate 放到不出貨的 placeholder 資料夾；--debug 資料夾會存每個方向切好的零件和疊圖，零件切錯先看這個；--skeleton 每格畫紅線
python art_pipeline/characters_v5/puppet_sheet.py art_source/characters_v5/male_base/views art_pipeline/_build/puppet_rig male_novice_puppet --candidate

# 3. 進遊戲看：重新匯入，再用單機模式截圖，--dev-walk 會走一段
godot --headless --path . --import
godot --path . res://scenes/dev/playground.tscn -- --offline --map=meadow --body=male_novice_puppet --dev-gender=male --dev-walk=6,-8 --dev-shot=art_pipeline/_build/看.png --dev-shot-ms=2400

# 4. 看過可以，拿掉 --candidate 正式輸出到 assets/generated/sprites/characters/body/<名稱>/
```

攻擊的六格不是等距取的：`cbuild.ACTIONS` 攻擊那行的 `times` 說每一格取動作的哪個時間點，第 0 格是半拉回、第 1 格全拉回、第 3 格命中滿伸、後兩格收勢；引擎等出手時間時停在第 0 格，看起來就是蓄力再爆發。要改力道就改這六個數字。受擊、死亡、撿東西也各有一組 times，同一個地方改。
動作本身在 `puppet_poses.py`，每個動作每一格的骨頭角度、長度、位移直接寫在畫面上，改完跑第 2 步就看得到。
零件疊的順序是固定的剪紙慣例：遠的手臂、遠的腿、近的腿、軀幹、近的手臂、頭，在 `LAYER_ORDER`；同一條肢體末端先畫、根部蓋在上面。
關節補圓頭的多寡在 `JOINT_EXTEND_RATIO`，短褲歸軀幹靠 `PELVIS_STRETCH` 和 `RADIUS_TUNE`，肩膀那塊衣服留給軀幹靠 `UPPER_ARM_TRIM` 和 `ARM_COLOR_CORE`，
小腿、腳、前臂最多轉幾度在 `ROTATION_LIMIT_DEG`；腳是自己的零件，肢體接成鏈的順序在 `CHAIN_PARENT`。
像素圖來源要加 `--pixel`：整條在 1 倍做、最近點取樣、不重畫描邊、輸出標 nearest。176×232 那種一格一格畫的圖放大兩倍再縮回來會糊成鋸齒，使用者 09-24 在創角畫面看到就退回了。

切錯零件的調法：頭的圓大小 `HEAD_CIRCLE_SCALE`、下巴 `HEAD_CHIN_STRETCH`、零件重疊 `PART_OVERLAP_PX`、
側面手腳併一條的門檻 `MERGE_RATIO` 都在 `puppet_sheet.py` 最上面；手臂往身體收的角度 `ARM_ADDUCT_DEG`、擺手幅度在 `puppet_rig.py`。
裝備照第 3 節掛在同一副骨架上算成圖層，不用重做身體。

## 2. 怪物

輸入：四視圖，`art_source/monsters/南門/<怪>/views/` 裡 front、left、back、right 四張，白底，你自己畫。
左右對稱的怪可以只畫左側面，鏡射當右側面：

```
python -c "from PIL import Image, ImageOps; ImageOps.mirror(Image.open('art_source/monsters/南門/水晶兔/views/left.png')).save('art_source/monsters/南門/水晶兔/views/right.png')"
```

怪物走 2D 紙偶：四視圖直接當方向圖，動作是整張圖以腳底為軸的傾斜、彈跳、壓縮、撲、倒下。
臉和線條就是你畫的，一隻幾秒。

```
# 1. 組圖集。--candidate 放 placeholder 不出貨；拿掉就直接寫進 assets/generated/sprites/monsters/<art.sheet>/
python art_pipeline/monsters_v2/mpuppet.py horn_slime art_source/monsters/南門/史萊姆/views

# 2. 進遊戲看：重新匯入，站到出生點旁邊用最近的鏡頭距離截圖；出生點座標在 data/maps/meadow.json
godot --headless --path . --import
godot --path . --resolution 1280x720 res://scenes/dev/playground.tscn -- --offline --map=meadow --dev-spawn=9,-10 --dev-shots=art_pipeline/_build/shots --dev-shot-distance=24 --dev-quit-after-ms=5000
```

新的怪要先在 `data/monsters.json` 加一筆，art 欄位的 sheet 就是圖集資料夾名，大小照 art.height、取景照 art.view_m，
覺得太小改那個數字重跑；frame_px 照密度政策從 view_m 算，測試會擋。art.motion 選走路的樣子：`hop` 跳、`waddle` 左右搖著走、`stomp` 重踏。
耳朵、角、葉子這些突出的部位會自動切出來跟著身體甩，跑的時候會印每個方向切到幾個部位；切錯就調 `mpuppet.py` 最上面的 APPENDAGE_ 常數。
動作的幅度在 `mpuppet.py` 的 `motion` 和 `_walk`。四隻腳會跑的怪這套只會整隻晃加部位甩，要腿真的走得另外切腿，還沒做。

## 3. 裝備與裝飾

2026-09-23 深夜起裝備走 2D 紙娃娃：畫一張武器或頭飾的圖，`puppet_layer.py` 照紙偶骨架每一格的接點把它疊成和身體同畫格的圖集，
換裝只換這一層，身體不用重做。男女共用同一份身體，一件裝備出一份；引擎會先找名稱接 `_male`、`_female` 的那一份，沒有才找共用的，之後男女身體分開時再用。

```
# 骨架和身體要同一份：先照第 1 節第 1 步出 rig
python art_pipeline/characters_v5/puppet_layer.py art_pipeline/_build/puppet_rig assets/generated/sprites/characters/body/male_novice 圖.png Knife --socket hand_r --grip 0.18,0.9 --axis -52 --length 0.35
```

圖要給一個資料夾，裡面 s、sw、w、nw、n 五張各自畫：正面看的刀是窄的、側面是整片，一張圖轉角度掛在身上每個方向都不自然，使用者 09-24 退回過。資料夾裡可以放 layer.json，每個方向各自給 grip、axis、angle、length，沒寫的用命令列的值。只給一張 png 時正面背面壓到 45% 寬當暫用。
`--grip` 是握把在圖裡的位置比例，`--axis` 是圖裡刀尖指向的角度，右邊 0、上面 -90；`--length` 是圖在世界裡幾公尺；
`--angle` 讓刀尖相對前臂再轉幾度，0 就是順著前臂往外指。頭飾和髮型用 `--socket head`。

側面和斜向的武器一律掛在近鏡頭那隻手，不管 `--socket` 寫 hand_r 還是 hand_l：面向左邊時右手在身體後面，掛右手整把刀被身體擋住，而且側面攻擊揮的就是近的那隻手。鏡射成面向右邊時刀會換到右手，RO 也是這樣。正面和背面照 `--socket` 掛。
名稱要等於道具的 `model_attachment`，初心者小刀是 `Knife`。第一把小刀是拿道具圖示 `assets/ui/icons/items/knife.png` 做的，
正式的要畫一張大一點的圖換掉。每一格在身體前面還是後面照手和軀幹的深度加每個方向的容許值算，在 `FRONT_TOLERANCE_M`。

下面 3D 那條留給沒有畫的東西。

### 3b. 3D 網格算圖層

武器掛在 `hand_r` 或 `hand_l`、頭飾和髮型掛在 `head`、披風掛在 `back`、鎧甲外觀掛在 `body`，
都是專案標準骨架上的掛點。算角色的時候多給 `--layer`，cbuild 用同一顆相機把掛上去的網格
在每一格單獨算成一張同畫格、同錨點的圖，遊戲把那一格直接疊在身體那一格上面，位置天生對齊。
圖層的名稱要等於 `data/items.json` 那件道具的 `model_attachment`（劍是 `1H_Sword`、匕首是 `Knife`），
遊戲裝上那件道具就會自己找 `characters/layers/<名稱>/`。

```
# 身體和一把單手劍一起算；--layer 可以重複給。網格直接拿 assets/generated/models/characters/ 裡的武器、鎧甲、披風、頭盔
blender -b --factory-startup --python-exit-code 1 -P art_pipeline/characters_v5/cbuild.py -- male_novice --source art_source/characters_v5/male_novice/mesh.glb --job novice --candidate --layer 1H_Sword=assets/generated/models/characters/weapon_sword.glb@hand_r
```

輸出在 `assets/generated/sprites/characters/layers/<名稱>/`（候選版在 placeholder 底下），meta 多三個欄位：
`socket` 掛點、`body` 陪它算的身體、`order` 每一格圖層在身體前面（1）還是後面（-1），引擎照它決定誰壓誰。
所有角色共用同一副骨架比例，所以一件裝備只要算一份，不用每個職業各算一次。
掛上去的方向不對就改 `cbuild.py` 的 `LAYER_ROTATION_DEG`，那是每個掛點一組角度。

### 3c. 像素紙娃娃：身體和每一層一起算，2026-09-27

角色改成像素畫風之後的換裝產線。身體和頭髮、帽子、武器在同一支程式裡同一格一起算，每一層各自像素化、各自描邊，
除了身體以外裁到內容外框，引擎照每一格的槽位疊。格式在 `docs/精靈圖規格.md`「紙娃娃圖層」。
**這台不用 Blender**：骨架改由 `rig2d.py` 照同一組比例和同一顆 30 度相機算，幾秒。

```
# 1. 骨架，幾秒：照視圖量頭頂、脖子、肩、胯、兩腳，比例照 cbuild.CARD_SPEC
python art_pipeline/characters_v5/rig2d.py art_source/characters_v5/male_base/views art_pipeline/_build/rig2d

# 2. 身體加圖層，一份約三分鐘。--height 180 是一比一、90 是一半的像素放大兩倍；輸出資料夾隨便給，先不要直接寫進 assets
python art_pipeline/characters_v5/paperdoll.py 輸出資料夾 --height 180 --rig art_pipeline/_build/rig2d/rig.json --layers hair_back,hair_front,hat_a,hat_b,knife

# 3. 送審圖和對齊報表：換裝對照、走路 GIF、像素化前後、帽子換色差異、武器前後換邊、每格報表
python art_pipeline/characters_v5/paperdoll_review.py 180的輸出 90的輸出 送審資料夾 --stone 石板.png --grass 草地.png --rig art_pipeline/_build/rig2d/rig.json
```

石板和草地是遊戲截圖切下來的一小塊，單機截城鎮：`godot --path . --resolution 1280x720 res://scenes/dev/playground.tscn -- --offline --map=town --dev-shot=town.png --dev-shot-ms=9000 --dev-quit-after-ms=20000`。
現在的頭髮、兩頂帽子、刀是 `testpieces.py` 畫的幾何測試件，只用來驗換裝，不出貨；正式的來源圖見下面 3d。

### 3d. AI 生圖層，方案，還沒實作，要在你的 Windows 上跑

2026-09-27 製作人轉達：使用者一個人開發，不另外請美術，圖層的來源圖由 AI 生，這台雲端沒有 GPU，ComfyUI 在你的電腦上。
試過的教訓都在接手紀錄 2.0b 到 2.2f 和第 4 節：**每一格叫模型重畫一次，一致性一定求不來；叫模型換視角，俯角補不了；叫模型直接出像素圖，格子和調色盤都是亂的。**
所以這條只叫 AI 做一件事：**在素體每個方向的原圖上，把頭髮、帽子、武器「畫上去」**，一個方向一張、一件東西五張，
視角、俯角、比例、位置全部由素體的原圖定；動作、每一格、像素化、描邊、裁切全部交給 `paperdoll.py`。

每一層每個方向生什麼：

| 圖層 | 餵給模型的圖 | 遮罩，只准改這一塊 | 生出來之後怎麼拆 |
|---|---|---|---|
| 頭髮 | 光頭素體那個方向的視圖，1024 | 頭的圓放大 1.25 倍，長髮往下延伸到肩；臉的範圍挖掉 | 和原圖逐像素比，變了的就是頭髮；在原本頭的剪影裡的是前髮，剪影外、耳朵以下的是後髮 |
| 帽子、頭飾 | 光頭素體，不戴頭髮 | 帽子的外包絡：帽簷那一列以上、頭的圓放大 1.3 倍 | 同上，變了的就是帽子；帽身在帽簷以上要蓋得住頭髮的外包絡，拆完自動檢查 |
| 武器、盾 | 不給身體，白底 | 無 | 側面 w 先生、你挑一張；其他四個方向拿它當參考圖生，正面背面是刀背那一面 |

一致性怎麼顧：

- 先只生正面 s，一次四個種子，你挑一張；其他四個方向把挑中的那張當第二張參考圖，同一段提示詞、同一個種子、同一個模型。
  Flux 2 Klein 的 `ReferenceLatent` 可以接兩張，`art_pipeline/comfy/flux.py` 已經是這個接法
- 遮罩外面一顆都不准變：拆圖層是拿「和原圖的差」當透明度，遮罩外有變就代表模型動了臉，那一張直接丟
- 不寫任何和視角、俯角有關的詞，視角由餵進去的那張圖決定
- 顏色：生完照整件的顏色量一條 5 階的色階，名稱 `<部位>_<名字>`，寫進 `ramps.json`，像素化時鎖在那一條上；換染色就是換色階

步驟，打算做成一支 `art_pipeline/comfy/layer_gen.py` 加一個雙擊用的 `layer_gen.bat`：

1. 開 ComfyUI，桌面版要開伺服器那一個
2. `layer_gen.bat hair 短髮_01 "short messy brown hair, anime style, flat cel shading, dark outline"`：
   上傳五張視圖和遮罩，先生 s 的四張放進 `art_source/layers/短髮_01/raw/`，跳出一張對照圖讓你挑
3. 你挑好編號，同一支再跑一次帶 `--pick 2`，生其他四個方向，每個方向兩個種子讓你挑
4. 自動拆層、去背、存成 `art_source/layers/短髮_01/{s,sw,w,nw,n}_front.png`、`_back.png`，和視圖同一個座標，所以不用對齊
5. 自動跑 `paperdoll.py` 和 `paperdoll_review.py`，出送審圖

這一節是方案，程式還沒寫，實際的 ComfyUI 節點名稱要在你的電腦上照 `flux.py` 的接法驗過才算數。

## 4. 驗收

- 每做完一個就進遊戲看，不要整批做完才看。看的是遊戲鏡頭下的大小、方向對不對、腳有沒有陷地
- `godot --headless --path . --script res://tests/run_tests.gd`，圖集格式錯了測試會直接講要改哪個欄位
- 檢查圖每個方向都要看，壞的那一面常常不是你在修的那一面

## 5. 常見問題

| 現象 | 原因和做法 |
|---|---|
| 側面圖裡單邊的東西跑到另一側 | 右側面是鏡射來的，這隻不對稱，要另外產真正的右側面 |
| 角色在遊戲裡比別人大或小 | cbuild 會把身高縮到 1.875 公尺，看檢查圖裡有沒有把武器或雜物算進身高 |
| 某一格碰到畫格邊緣 | cbuild 會印出來是哪一格碰到哪一邊；動作太大就換動作，或改 `data/appearances.json` 那個職業的攻擊動作 |
| Blender 印 No module named PIL | 正常，產線不用 Pillow；是自己加的程式才要 |
