# 操作手感：參考作品與差距分析

2026-09-16 訂。使用者第二次試玩後說還是不順，指定研究《夢之形 Shape of Dreams》和《靈谷 SpiritVale》。
這份是差距分析：每一條機制寫「他們有什麼、我們現在是什麼、能不能做、代價多少」，不是心得。
時間契約和數值不在這份裡，那兩份分別是 `docs/打擊感規格.md` 和 `docs/自有數值系統.md`。

## 1. 先修正一個前提：兩款的參考價值不一樣

| | 夢之形 | 靈谷 SpiritVale |
|---|---|---|
| Steam | app 2444750，2025-09-11 | app 3767850，2026-07-16 搶先體驗 |
| 評價 | 極度好評，繁中 1101 篇 | **大多負評**，繁中 1261 篇；全語言 4744 篇「意見不一」，近期 606 篇大多負評 |
| 拿來當什麼 | **手感的正面範本** | **反面教材，而且剛好驗證了我們已經做過的事** |

靈谷是「照 RO 做而且真的上市了」沒錯，但它現在是負評居多，不能當品質標竿。
把它的負評讀完之後更有價值的發現是：**罵的幾乎都不是戰鬥手感，是伺服器**。
延遲、斷線、區域伺服器不穩、封禁申訴、RMT 和經濟，佔了負評的絕大多數。

戰鬥相關的抱怨只有一條，但那一條很重要：

> 「怪物實際的座標位子 與玩家看的到不一致 導致攻擊根本無法正常攻擊目標」
> 「怪都在飄移 打怪還要猜他們在哪」

那正是內插延遲和修正沒做好的症狀，也正是 `docs/打擊感規格.md` 第 4 節已經處理掉的東西：
內插延遲 100 毫秒改 60 毫秒之後，怪物畫面位置落後伺服器平均 34 毫秒、最大 68 毫秒。
所以靈谷給我們的結論是「別在這裡翻車」，而不是「照它做」。
順帶提醒第 6 節那條待辦：接遠端伺服器之後一定要重新量抖動再定內插延遲，那就是他們掉下去的坑。

## 2. 夢之形：觀察到的機制

來源：Steam 商店頁與繁中評論、Steam 討論區 `WASD vs. Mouse Controls`
和 `How to get more control of my movement`、日文攻略站整理的兩套操作配置。

| 觀察 | 出處 |
|---|---|
| 兩套操作配置：MOBA（右鍵移動、左鍵普攻、QWER 技能）和 WASD＋滑鼠（WASD 移動、左鍵朝滑鼠方向普攻、右鍵/Q/E/R 技能） | 討論區、攻略站 |
| **WASD 模式可以一邊持續移動一邊普攻**，這是玩家選它的主要理由 | 討論區原文「WASD lets you move constantly while also being able to AA」 |
| **移動方向和瞄準方向分開**：可以往側面走，同時對著前方的敵人打 | 攻略站，原文說它「特別擅長一邊瞄準前方敵人一邊橫向移動」 |
| 技能是瞄準的 skill shot，不是選中目標後施放 | 商店頁與評論 |
| 閃避是隨時扣著的鍵，玩家形容「隨時睜大眼睛扣著閃避」「躲招躲到眼睛在燃燒」 | 繁中評論 |
| 閃避接普攻是輸出手段之一，不只是保命 | 繁中評論「只能依賴閃避平A來做輸出」 |
| **施放前的定身被玩家點名是爛設計**：一個技能要在怪面前停 0.5 秒才打下去，被拿來當負面例子 | 繁中評論 |
| 技能冷卻縮減是主要 build 軸線，暗示循環短、手一直有事做 | 繁中評論「無腦堆技能冷卻與傷害」 |
| 移動速度加成被當成強角的特徵 | 繁中評論「自帶跑速加乘 25%」 |

一句話：**手一直在動，而且移動、瞄準、閃避三件事互不搶佔。**

## 3. 差距分析

狀態欄：✅ 已經有；⚠️ 有但不夠；❌ 沒有。

| 機制 | 他們 | 我們現在 | 能不能做 / 代價 |
|---|---|---|---|
| 出手中還能操作 | 一邊移動一邊普攻 | ❌ **出手動作期間方向鍵完全沒反應**。實測 Lv1 amotion 580 毫秒、adelay 1160 毫秒，等於每個攻擊循環有一半的時間按鍵被默默吃掉 | **已修，見第 4 節。**這是這次最大的一項 |
| 移動取消出手 | 有，隨時能走 | ⚠️ 動畫層本來就可以被移動打斷，但模擬層照樣鎖住位置，所以看得到動畫斷了人卻不動 | **已修**，和閃避取消出手同一條規則 |
| 閃避有無敵幀 | 有，而且是核心 | ✅ 2026-09-16 做好：2.4 公尺 300 毫秒、無敵 40 到 240 毫秒、冷卻 900 毫秒 | 已完成 |
| 閃避取消出手 | 有 | ✅ 已完成，代價是放棄那一下的傷害 | 已完成 |
| 命中回饋即時 | 有 | ✅ 收到就播：傷害數字、閃白、停頓、擊退、火花、音效同一幀 | 已完成 |
| 移動與面向分離 | ✅ 往側面走、對前方打 | ❌ 角色永遠面向移動方向，只有鎖定目標時例外 | 做得到，但要在 `entity.state` 加一個面向欄位並在協定和快照裡同步，紙片角色的八方向圖也要照新的面向取圖。**中等成本，需要決定** |
| 滑鼠瞄準的 skill shot | ✅ 技能全部用瞄的 | ❌ `data/skills.json` 36 個技能裡 13 個 `active_target` 鎖定目標、10 個 `active_ground` 指定地面，沒有一個是朝方向射的 | **這是真正的設計決定，不由我決定。**成本見第 5 節 |
| 技能自帶位移 | ✅ 突進、閃現 | ❌ 沒有任何技能會移動施法者。空間屬性只推開別人 | 做得到，機制和閃避的 `_dodge_advance` 同一套，但要在技能資料加位移欄位並決定哪些技能有。**中等成本，需要決定** |
| 短冷卻、手一直有事做 | ✅ 冷卻縮減是主要 build 軸線 | ⚠️ 36 個技能只有 6 個有冷卻，中位數 5500 毫秒；其他靠 SP 和詠唱時間擋 | 資料層可調，但屬於 `docs/自有數值系統.md` 的平衡決定 |
| 施放不定身 | ✅ 定身被當成爛設計點名 | ❌ **13 個技能有詠唱，詠唱期間完全不能動，走一步就中斷**。而且詠唱時間隨技能等級變長：火箭 Lv1 是 500 毫秒、滿級 3200 毫秒，雷球滿級 3800 毫秒，有的還再加 1400 毫秒的施法後延遲 | 這正是夢之形玩家罵的那件事乘以好幾倍。**需要決定**，見第 5.1 節 |
| 怪物有可閃的預警 | ✅ 躲招是核心循環 | ✅ 已經有：範圍攻擊和詠唱都發預警事件，資料裡 900 到 1600 毫秒 | 已完成。閃避的無敵窗就是照這個區間定的 |
| 網路位置和畫面一致 | — | ✅ 內插延遲 60 毫秒，怪物落後平均 34 毫秒 | 已完成，正是靈谷翻車的地方 |
| 看得清楚自己在幹嘛 | 俯視但角色佔畫面夠大 | ✅ 角色 1.875 公尺、貼圖 180 像素高；鏡頭預設 52 公尺時 1080p 上約 148 像素，滾到 42.73 是一比一 | 已完成。上限就是照角色還讀不讀得出來訂的 |

## 4. 這次做掉的：出手中按方向鍵立刻就動

改之前的行為，實測不是推測：鎖定目標出手之後按方向鍵，
指令會被接受、攻擊鎖定會解除、但**位置要等整段出手動作跑完才開始移動**。
Lv1 初心者是 580 毫秒，攻擊間隔 1160 毫秒，**每個攻擊循環有一半的時間操作是無效的**。
使用者說的「target and wait」「很死」，最直接的來源就是這 580 毫秒。

改法是把它併進已經存在的那條規則，全遊戲只有一條「取消出手」的規則：

> 移動或閃避打斷還沒結算完的出手時，那一下的傷害不算；
> 下一次出手的時間只會被往後推、不會提前。

所以取消永遠只有代價沒有好處，不需要額外的防作弊機制。伺服器權威、時間契約、
amotion 和 adelay 的數字全部沒有動，動的只有「這段時間允不允許移動」。

| 量的東西 | 改前 | 改後 |
|---|---|---|
| 出手後按方向鍵到真的開始移動 | **580 毫秒**，等於整段 amotion | **30 毫秒**，下一個 tick |
| 佔攻擊循環的比例 | 50% 的時間操作無效 | 0 |
| 被取消那一下的傷害 | 照樣結算 | 不結算，並發 `attack_cancel` 事件 |
| 攻擊間隔 adelay | 1160 毫秒 | 1160 毫秒，沒有變 |
| 怪物的出手 | 有承諾 | 有承諾，完全不受影響，玩家才有東西可以閃 |

逐幀確認，`--dev-feel` 在 60fps 固定步進下跑同一段腳本：
第 280 幀送出攻擊、281 幀 `1H_Melee_Attack_Stab` 開始、281 到 300 幀速度都是 0，
第 300 幀按方向鍵、**第 302 幀就回到 `Running_A` 而且速度 3.5**，中間只差 2 幀 33 毫秒。
改之前這裡要等到第 335 幀左右，也就是整段 amotion 跑完。圖在 scratchpad 的 `cancel/cancel_strip.png`。

怪物刻意不套用這條規則：牠們的出手必須是有承諾的，不然就沒有可以閃的東西。
守住的測試在 `tests/test_dodge.gd`：立刻就動、被取消的沒有傷害、
一直取消不會變成更高的輸出、怪物不受影響。

單機和連線走同一條路：連線是 `move.to` 和 `move.dir` 進 `_cancel_attack_for_move`，
單機的位置是客戶端自己推的，所以另外走 `command_move_intent` 進同一段。
`command_stop` 沒有動，關掉自動攻擊時送的那一則照樣打得到，那是第 3 節的既有契約。

## 5. 要你決定的三件事

這三件都會改變技能的定義方式，不該由實作的人自己決定。按價值排序。

### 5.1 詠唱期間不能動，最長 3.8 秒

2026-09-17 已經定案一部分：**詠唱中的移動指令改成整個拒絕，人不動、詠唱也不斷，只有閃避翻滾能打斷**。
「走一步就中斷」那個問題沒有了，下面三個選項談的是詠唱時間本身要不要縮短，還沒決定。
規則寫在 `docs/打擊感規格.md` 第 4.1 節。

13 個技能有詠唱，以前走一步就中斷。夢之形的玩家把「停 0.5 秒才打下去」當成爛設計的例子，
我們滿級的火箭要 3200 毫秒、雷球 3800 毫秒，是它的六到八倍。

另外有一件事單獨拿出來講：**詠唱時間是隨技能等級變長的**。
火箭 Lv1 詠唱 500 毫秒，練到滿級變成 3200 毫秒。
也就是說玩家把技能練強的同時，那個技能會變得越來越難用、越來越容易被打斷。
這不只是手感問題，是個奇怪的成長誘因，值得你一起決定要不要改掉。

三個選項：

| 選項 | 代價 |
|---|---|
| 縮短詠唱時間 | 只改 `data/skills.json` 的數字，最便宜；但這是平衡改動，要同步 `docs/自有數值系統.md` |
| 詠唱期間可以走，移動不中斷但降速 | 要改 `_move_tick` 的詠唱閘門和預測層，中等；改變術士的玩法 |
| 改成瞬發加冷卻 | 最貴，整個法系的節奏重做 |

我的建議是先做第一個，量完再看要不要做第二個。

### 5.2 移動方向和面向分離

讓角色可以往側面走、對著前方打。這是夢之形 WASD 模式最被稱讚的地方。
代價：`entity.state` 要加面向欄位並同步、紙片角色要照新面向取八方向圖、
輸入層要決定面向來自滑鼠還是鎖定目標。不改任何技能資料。
**這一項我認為投資報酬最高，而且不動 skills.json。**

### 5.3 瞄準式技能

把 `active_target` 和 `active_ground` 改成朝方向射的 skill shot。
代價最大：`data/skills.json` 全部 23 個主動技能的定義要重寫，
伺服器的 `_aim`、命中判定、預測層、怪物 AI 的閃躲、以及所有技能特效的方向都要改。
好處也最大，那是「手感扎實」的核心。
**這一項請你先決定要不要走，不要我自己動手。**
