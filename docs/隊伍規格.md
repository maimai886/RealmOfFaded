# 隊伍規格

2026-09-16 訂。照 RO 與 rAthena 的隊伍系統做，出處寫在每一節。
純規則在 `src/core/party.gd`，伺服器在 `server/services/party_service.gd`，介面在 `src/ui/party_window.gd`。
封包契約補在 `docs/伺服器架構.md` 第 3 節，惡意客戶端測試記在第 11 節。

## 2. 資料

隊伍紀錄存在資料庫的 `parties/<隊伍 id>`，和角色、帳號一樣有 HMAC 簽章和版本日誌，改檔會被隔離。
角色存檔**不存**隊伍欄位，隊伍紀錄是唯一權威；改角色檔塞一個隊伍 id 進去沒有用。

```
{
  id, server_id, name, leader: 角色 id, item_share: bool, created_at: unix 秒,
  members: { 角色 id: {name, joined_at: 加入順序} }
}
```

- `joined_at` 越晚加入越大，同一個隊伍裡不重複，只拿來排列表順序
- 舊紀錄的 `loot_turn` 是以前輪流分配的排隊號碼，讀進來時丟掉
- 伺服器啟動時把所有隊伍讀進記憶體並建立「角色 id → 隊伍 id」索引；讀不到或格式壞掉的不載入，成員就變成沒有隊伍
- 同一個角色出現在兩份隊伍紀錄裡時只認先讀到的那一份，另一份把他拿掉
- 成員變動、隊長變動、開關道具分配時立即存檔；載入時修正過的紀錄載完一起存
- 最後一個成員離開時整筆刪除

## 3. 指令與規則

| 指令 | 誰可以送 | 檢查 |
|---|---|---|
| `party.create` | 沒有隊伍的人 | 名稱 1～23 字；隊伍 id 由資料庫 `next_id("p")` 發 |
| `party.invite` | 隊長 | 不能邀自己、對方要在線上且同一台伺服器、對方沒有隊伍、沒有還沒回應的邀請、隊伍沒滿、同一個人連續邀請至少隔 1 秒 |
| `party.accept` | 被邀請的人 | 邀請存在、沒過期、隊伍 id 對得上、隊伍還在、自己還沒有隊伍、隊伍沒滿 |
| `party.refuse` | 被邀請的人 | 同上的前幾項；拒絕會通知邀請人 |
| `party.leave` | 任何成員 | 在隊伍裡 |
| `party.kick` | 隊長 | 對方在隊伍裡、不能踢自己；離線的成員也踢得掉 |
| `party.leader` | 隊長 | 對方在隊伍裡而且**在線上**，不能轉給自己 |
| `party.option` | 隊長 | 切換道具分配方式 |
| `chat.say` channel 是 `party` | 任何成員 | 在隊伍裡；全隊收得到，不分地圖 |

失敗原因：`already_in_party`、`not_in_party`、`not_leader`、`not_member`、`party_full`、`target_in_party`、
`target_offline`、`target_self`、`already_invited`、`no_invite`、`invite_expired`、`party_not_found`、
`bad_party_name`、`same_leader`、`rate_limited`、`server_error`。

### 邀請
- 邀請記在**被邀請者**身上，`{party_id, from_id, from_name, until_ms}`，30 秒沒回應就失效
- 被邀請的人斷線時邀請作廢；邀請人斷線不影響，接受之後隊長顯示離線
- 每個人同時只會有一個還沒回應的邀請，第二個邀請回 `already_invited`

### 隊長離開
rAthena 的 `party_member_withdraw` 對隊長沒有特別處理。本作改成**最早加入的成員接任**並公告，
不然隊長離線後沒有人能邀請和踢人，隊伍等於廢掉。角色被刪除時一樣從隊伍拿掉並接任。

## 4. 經驗分配

照 rAthena `src/map/party.cpp` `party_exp_share`：先算合格人數，經驗除以人數，再乘上平均分配加成。

合格成員要**同時**滿足：
1. 在同一張地圖
2. 活著
3. 離怪物死亡位置在 `Party.SHARE_RANGE_M` 24 公尺內
4. 全隊合格成員的基本等級最高與最低差不超過 15 級，超過整隊都不分，只給擊殺者

公式，`c` 是合格人數：

```
每人基本經驗 = (怪物基本經驗 / c) * (100 + 10 * (c - 1)) / 100
每人職業經驗 = (怪物職業經驗 / c) * (100 + 10 * (c - 1)) / 100
```

整數除法無條件捨去，順序和 rAthena 一樣先除再加成。例：寶箱怪 40 經驗，兩個人各拿 `40 / 2 * 110 / 100 = 22`。

- 24 公尺是視野格子 3×3 最遠看得到的距離，畫面上看得到的隊友一定在範圍內。rAthena 只要求同地圖，
  這裡加距離限制是為了擋「隊友在地圖另一頭掛機也拿經驗」
- 離線和斷線留在地圖上的成員不算合格成員
- 每個拿到經驗的人各收到一則 `reward` 事件，`shared` 為 true 代表是隊伍分配；各自寫一筆 `exp.gain` 稽核

## 5. 道具分配與擁有權

### 擁有權
掉落物 3 秒內只有擊殺者能撿（`DROP_OWNER_PROTECT_MS`，照 `item_first_get_time`）。
隊伍**開著道具分配**時，擁有權期間同隊成員也能撿，照 rAthena `pc_takeitem` 的 party item share。
沒開分配時隊友和路人一樣撿不到，回 `not_owner`；3 秒過後誰都能撿。

**王的掉落**，2026-09-25 照《奪色世界規劃書》第 5.3 節做：資料寫 `boss` 或 `mini_boss` 的怪，
掉落歸**傷害最高的一方**，隊伍的傷害加總算一方，那一方裡打最多的人當擁有者，擁有權 10 秒 `DROP_OWNER_PROTECT_BOSS_MS`。
擁有者那一隊的成員不管分配設定都撿得到，撿起來之後才照個人或隨機分。哪一方由伺服器的 `party_service.damage_group` 決定，
傷害記在怪物的 `damage_by`，超過剩下血量的部分不算。

### 隨機分配
2026-09-24 使用者定的：隊伍的道具分配只有**個人**和**隨機**兩種，取代原本照 rAthena 的輪流分配。
紀錄欄位沿用 `item_share`，false 是個人，true 是隨機，舊存檔不用搬。

- **個人**：誰撿到就是誰的。
- **隨機**：撿起來的東西隨機給一個隊員，不是給撿的人：
  1. 候選人是同地圖、活著、在 24 公尺內的成員
  2. 伺服器用自己的亂數把候選人洗牌，照洗完的順序試，第一個背包**放得下**的人拿到
  3. 都放不下就給撿的人；撿的人也放不下才失敗，回 `overweight` 或 `inventory_full`

亂數在伺服器，客戶端影響不了；測試固定種子，見 `test_party.gd` 的
`test_loot_order_is_a_random_shuffle_of_members` 和 `test_security_party.gd`。

- `pickup` 事件多一個 `to` 欄位，是實際拿到的人的實體 id
- 稽核 `item.pickup` 在東西給了別人時多記一個 `to`，是實際拿到的角色 id
- 撿的人和收的人各自看到訊息：「撿到的 X 分配給了 Y」「Y 撿到的 X 分配給你」

## 6. 推送與介面

| 推送 | 時機 | 內容 |
|---|---|---|
| `party.info` | 成員變動、上下線、換地圖、進地圖 | `{id, name, leader, item_share, members: [{id, name, leader, online, map, map_name, level, job_id, entity_id}]}`；沒有隊伍時只有 `{id: ""}` |
| `party.invited` | 被邀請時 | `{party_id, party_name, from, timeout_ms}` |
| `party.vitals` | 每 1 秒 | `{members: [{id, entity_id, hp, max_hp, sp, max_sp, level}]}`，只含同一張地圖的成員，那張地圖上只有一個成員時不送 |
| `chat.message` channel `party` | 隊伍頻道和加入離開這類通知 | 通知的 `from` 是空字串 |

- `entity_id` 只有在收訊息的人同一張地圖時才是實體 id，否則是 -1；跨地圖不洩漏別張地圖的實體編號
- 隊伍視窗 `Alt+Z`，也在基本資訊視窗的按鈕列
- 沒有隊伍時顯示建立隊伍的輸入欄；有隊伍時顯示名稱、人數、隊長（★）、成員列表、道具分配方式按鈕、
  邀請欄、離開、踢出、轉讓
- 成員列顯示名字、等級、職業、所在地圖；同一張地圖的隊友多一條 HP 和 SP，數值來自 `party.vitals`
- 離線的成員名字變灰，顯示「離線」
- 邀請彈窗在畫面中央上方，有接受、拒絕和倒數，30 秒到自動拒絕
- 隊友的名字在畫面上用隊伍色 `UiTheme.TEXT_PARTY`，腳下多一條 HP 條（`player.gd` 的 `set_party_member`）
- 聊天視窗多一個「隊伍」分頁；`/p ` 開頭或停在隊伍分頁打字都是隊伍頻道

## 7. 防作弊

| 攻擊 | 做法 |
|---|---|
| 洗邀請騷擾別人 | `party.*` 每秒 3 則（`rate_limiter.gd` 的 party 桶），同一個人連續邀請至少隔 1 秒，被邀請的人同時只有一個邀請 |
| 亂接受別人的邀請 | 邀請記在被邀請者身上並綁隊伍 id，送別人的 `party_id` 回 `no_invite` |
| 過期的邀請 | 30 秒失效，伺服器每輪清掉過期的 |
| 非隊長踢人、轉讓、改分配 | 每則指令都重新檢查隊長身分，不信任客戶端畫面 |
| 轉讓給不存在或離線的人 | 對方要在成員名單裡而且在線上 |
| 塞爆隊伍 | 12 人上限在邀請和接受時各檢查一次 |
| 分身或離線角色吃經驗和道具 | 合格成員要在線、活著、同地圖、在 24 公尺內；離線的成員什麼都拿不到 |
| 等級差很多的小號吸經驗 | 等級差超過 15 級整隊不分，只給擊殺者 |
| 離開再加入插隊拿道具 | 排隊號碼制，重新加入一定排到隊尾 |
| 竄改隊伍存檔 | 隊伍紀錄和角色檔一樣有簽章和版本日誌，改過的移到隔離區不載入，成員變成沒有隊伍 |
| 改角色檔偽造隊伍 | 角色檔沒有隊伍欄位，隊伍只看隊伍紀錄 |
| 邀請中斷線 | 被邀請的人斷線時邀請作廢；隊長斷線時隊伍還在 |
| 隊伍頻道洗頻 | 和一般聊天共用每秒 2 則的桶；被踢之後立刻不能再送 |
| 偷聽隊伍頻道 | 沒有隊伍或不是成員回 `not_in_party`，訊息只送給線上成員 |

## 8. 和 rAthena 不同的地方

| 項目 | rAthena | 本作 | 理由 |
|---|---|---|---|
| 平均分配加成 | 設定預設 0 | 每多一人 +10% | 官方 Renewal 的行為，組隊才有誘因 |
| 分配範圍 | 只看同地圖 | 同地圖再加 24 公尺 | 擋掛機吸經驗，範圍取畫面看得到的距離 |
| 道具分配 | 輪流，成員索引當游標 | 個人或隨機 | 使用者要隨機；隨機也不用擔心排隊插隊這類漏洞 |
| 隊長離開 | 沒有特別處理 | 最早加入的人接任 | 不然隊伍沒有人能管理 |
| 轉讓隊長 | 預設不限同地圖 | 對方要在線上 | 轉給離線的人等於沒有隊長 |
| 經驗分配方式 | 可選平均或各自 | 只有平均 | 先做一種，介面不用多一個選項；之後要加再開 |
| 隊伍名稱 | 建立後可改 | 不能改 | 還沒有需求，少一個指令少一個攻擊面 |

## 9. 還沒做

- 隊伍經驗分配方式（平均／各自）切換，目前固定平均
- 小地圖上的隊友位置點；RO 有，`party_update_interval` 就是為它設的
- 隊伍倉庫、隊伍任務、隊伍副本
- 跨伺服器隊伍：目前 `party.invite` 只找同一台伺服器的線上玩家
- 隊長離線太久自動轉讓；現在要等他上線或由新隊長接任（最後一個離開才解散）
